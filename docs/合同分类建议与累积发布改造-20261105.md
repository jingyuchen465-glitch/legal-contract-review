# 合同自动分类、分类建议中心与累积发布

本次改造使用功能开关 `LEARNING_CATALOG_ENABLED`。需先执行数据库迁移014；默认关闭。回退时关闭开关并切回上一发布目录，保留新增整理记录和历史包，不执行迁移回滚。

## 使用流程

1. 上传后后台解析正文，先显示大类、子类、业务标签、理由及原文依据，再继续识别主体和准备审查事项。正文不足显示待确认。原有审查信息确认页可以修正类型及海外仓场景标签。
2. 法务最终确认后分段提炼，再全文归并。相同主题与适用边界才合并，程序保留独有检查点、例外、范例、原文及规则依赖；不规定每份合同的建议数量，允许零条。
3. “反馈与评测”页分为“技能建议”和“规则建议”，支持分类、业务标签、来源及状态筛选、分页，保留原人工反馈、标注和评测入口。已覆盖建议可人工恢复为待确认。
4. 采纳生成草稿，仍需提交审核和发布。新采纳C后保留已有A+B；只有明确编辑目标条目才修改A，停用需明确目标或原因。发布页显示保留、新增、修改和停用数量。并发基线变化返回409。
5. 正常替代的旧包称为历史快照；已采纳建议根据当前条目是否仍生效显示状态。超过20条按批装载并记录覆盖情况，编辑器每页10条。
6. 规则依赖以稳定编号和内容签名核对；新增其他规则不使无关技能失效，依赖内容变化仅排除受影响的方法并记录待复核原因。

## 海外仓场景

海外仓场地租赁和转租使用“跨境物流仓储合同／海外仓仓储服务合同”，通过“场地租赁、转租、仓储服务”区分业务。仅租赁或转租且没有仓储服务时，不自动装载旧的入库、盘点、出库审查项。人工明确重写并限定适用场景的规则按新范围匹配。

## 已有内容整理

“反馈与评测 → 已有合同分类与经验整理”先生成可审核清单，展示分类依据、建议归并及已发布方法迁移。勾选核对后才能应用。应用通过单事务校验合同版本、经验任务修订、源文件哈希及来源/目标包发布基线；同时迁移已有方法并保留来源。无效的准备中预分析会失效并要求重新准备。

原始提案、来源正文、历史预审快照及最终结论保持原记录；整理结果独立存为覆盖层。没有自动发布新法律标准。整理候选中的新规则/技能仍走草稿审核。

## 接口

- `GET /learning-proposals`：kind、categoryId、typeId、tag、state、contractId、taskId、page、limit。
- `GET/POST /learning-reorganizations`：读取候选、扫描合同生成候选。
- `POST /learning-reorganizations/:id/retry`、`.../apply`：重新生成、核对修订后应用。
- `POST /learning-tasks/:id/proposals/:proposalId/reopen`：恢复被判定已覆盖的建议。
- 原草稿编辑/采纳/审核/发布接口保留；累积保存使用 `removedItemIds` 明确停用，发布检查遗漏。

## 验证与运维

新增自动测试覆盖目录、unknown、长文全文综合分类、41条技能完整装载、A/B/C累积、明确停用、并发冲突、依赖规则签名、跨类别原子迁移及权限隔离。真实浏览器验证分区、筛选基础操作、编辑采纳发布、25条分页、历史候选核对与390像素手机宽度。

上线前保留数据库及原文件备份，确认至少10GB磁盘可用。先在隔离数据库运行回归及样本验证，再开启开关；PDF转换、OnlyOffice和现有历史审核使用原配置。模型测试不能代替法务对法律标准和复杂合同的验收。
