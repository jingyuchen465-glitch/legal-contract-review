# 法务经验管理与审核

本次实现覆盖法务经验页中的“审查技能”和“案例经验”。代码与前端构建已完成，采用隔离数据库和真实浏览器验收；尚未部署正式站点。

## 使用流程

- “新增知识”录入类型、标题、摘要、完整内容及适用条件，保存草稿后提交审核。
- 法务或管理员可审核本人或权限范围内其他人的内容。退回必须填写原因，退回后可编辑重提。
- 自动提炼的新内容同样保存为草稿；现有生效知识保留原状态。
- 编辑正式知识只修改后继草稿。审核通过才递增正式版本；已停用的知识发布新版后仍保持停用。
- 卡片支持查看、编辑、提交、审核、退回、启停、删除。搜索包含正式内容及草稿，支持类型、生效状态、审核状态筛选和分页。
- 永久删除清除该条知识和全部版本正文，不影响同来源其他条目。原始法务处理、生成数量、历史审查快照及不含正文的删除审计保留。
- “撤销整个来源”仍会停用该来源下全部知识，不能再审核发布或启用。知识详情、来源详情可互相跳转。

## 实现约定

- `la_agent_memories` 保存当前正式内容和管理修订号；`version=0` 表示尚无正式版，`revision` 用于并发控制。
- `la_agent_memory_versions` 保存正式历史与唯一待处理草稿，状态为 `draft / pending / rejected / published`。数据库部分唯一索引保证每条最多一份待处理草稿。
- 来源关联可空，人工创建记录 `origin=manual`。普通法务固定本部门，管理员及有全部门权限的法务可以指定部门。
- 来源记录新增修订号及冻结的生成数量，兼容没有完整历史审计的早期数据。
- 审查快照保留条目 ID、正式版本和完整内容。发布、停用、删除或撤销来源会标记旧审查待复核。新会话比较 ID 与版本，清理失效上下文；完成重新核查后，后续继续保留有效的新上下文。
- 快照读取与最终结果提交使用知识行共享锁，知识变更使用排他锁；并发变更后不能提交旧结果。历史快照保留原文，不随当前知识正文变化。

## API

全部接口位于 `/api/agent`，需要法务或管理员权限，并遵守部门边界。写请求需要 CSRF，除创建外均提供最近读取到的 `revision`，冲突返回 409。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/experiences` | `q/kind/state/review/page/pageSize` 服务端搜索分页，返回 `memories/total/page/pageSize/summary` 及来源记录 |
| POST | `/experiences` | 创建人工知识草稿 |
| GET | `/experiences/:id` | 正式内容、草稿、版本、审核意见及操作记录 |
| PUT | `/experiences/:id` | 保存唯一待处理草稿，待审核时不可编辑 |
| POST | `/experiences/:id/submit` | 提交并锁定草稿 |
| POST | `/experiences/:id/approve` | 审核通过，发布正式版本 |
| POST | `/experiences/:id/reject` | 退回，`note` 必填 |
| POST | `/experiences/:id/enable`、`/disable` | 单条启停 |
| DELETE | `/experiences/:id` | 永久删除 |
| POST | `/experience-sources/:id/revoke`、`/retry` | 撤销整个来源或重试失败整理，需来源的 `revision` |

正文限制沿用已有知识：标题 200 字、摘要 500 字、正文 12000 字；适用条件最多 20 条，每条 1000 字。

## 验收

本轮结果：前端构建通过；123 项单元测试、25 项原有 Agent 集成回归及 11 项新增知识管理/浏览器验收全部通过。最后一次隔离回归共执行 40 项（包含 4 项生成统计单元测试），无失败或跳过。

- `npm run build`：前端构建。
- `npm test`：原有单元测试。
- `node scripts/test-agent.mjs backend/test/agent-memory-results.test.js backend/test/integration/agent.test.js backend/test/integration/memory-management.test.js`：隔离 PostgreSQL 回归。
- 设置 `MEMORY_UI_QA=1` 运行上述命令：增加 Edge 浏览器验收，不使用正式数据或真实模型。
- 新测试覆盖存量迁移、两类知识完整审核流程、自审、正文版本隔离、跨部门权限、CSRF、203 条数据分页及正文搜索、并发编辑审核、知识变更与最终提交竞争、永久删除与历史数量/快照保留。
- 浏览器覆盖新增、修改、退回重提、发布、启停、删除、并发错误提示、筛选翻页及 390px 手机布局；截图与结果位于 `.local/memory-management/`。

## 发布步骤

1. 使用现有发布流程备份数据库与文件，安排 API 和 Worker 的停止/更新窗口。
2. 更新代码，执行 `npm run db:migrate`，应用 `020_agent_memory_management.js`；迁移保留现有生效知识并补建版本及生成数量。
3. 部署本次前端构建并重启 API、Worker。旧 Worker 不应在迁移后继续运行，避免仍按旧流程直接生成生效内容。
4. 验证存量知识可查看，新增内容以草稿保存，审核后才进入后续审查；正式站点无需创建或删除真实知识进行测试。

不通过删除版本表或自动回滚恢复旧发布；出现问题按既有备份恢复流程处理。
