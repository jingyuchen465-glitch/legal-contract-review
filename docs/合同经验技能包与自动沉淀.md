# 合同经验技能包与自动沉淀

本文件用于接手技能包、经验任务、版本固定或发布回退工作。线上版本、备份与验收回执以 [Agent 交接](AGENT交接-录音反馈修复与上线.md) 最新发布段落为准。

2026-11-05 起，默认页面改为按合同统一采纳、编辑和发布一个综合技能，后续确认更新同一技能。当前使用和文件加载机制见[一合同一综合技能](一合同一综合技能-20261105.md)。下文保留原技能接口说明；新版发布文件也参与实际预审，需连同数据库备份。

## 使用流程

1. “分类与规则中心 → 审查技能包”维护通用或某一合同类型的技能。规则保存检查项和判断标准；技能保存审查方法、条件、例外和修改范例。
2. “反馈与评测中心 → 合同经验整理”由管理员开启自动整理。仅开启后新确认的正式合同产生任务，不回填历史合同；示例试审及 `validationFixture` 跳过提炼。初始技能库为空。
3. 法务确认同意、附条件同意或不同意后，后台整理经验。合同详情显示整理中、待确认、无新增经验或失败。失败不改变已保存的法务结论，可重试。
4. 在经验列表核对原内容、建议内容、适用范围、原文证据及人工处理理由。可以编辑、忽略或采纳。最后一条提案处理后，本次页面仍保留该任务，方便进入草稿；也可勾选全部任务查找。
5. 新检查标准采纳为现有规则流程的草稿；方法与范例采纳为技能草稿。两者均经过“保存草稿 → 提交审核 → 发布”。技能依赖的新规则须先发布；通用推广在采纳和发布时均需明确确认。
6. 发布只影响新建预审。合同详情列出本次加载的技能，报告保存同一快照。空技能库照常审核。

“自动整理”表示自动生成候选提案，不代表自动学习生效。技能正文应使用【我方】【对方】【待确认期限】等占位符。附条件接受及拒绝意见须保留结论语境，不能变成无条件认可范例。

## 数据与版本

- 迁移：`backend/pilot/migrations/010_contract_skills.js`。`la_skill_versions` 保存技能正文、范围、状态、版本父节点、来源关联和规则版本依赖；`la_learning_tasks` 保存唯一结论 ID、来源、模型快照、提案、错误和修订号。数据库为正式存储，Markdown 为导出视图，不写入 Codex 技能目录。
- 经验任务与最终结论在同一事务写入，`decision_id` 唯一；事务消息发送到 `learning` 队列，由 Worker 调用现有模型。每任务数据库 advisory lock 防止重复执行；按提案语义去重，重试保留已采纳或忽略的提案。
- 输入包含确认稿、最终结论、人工处理记录及直接上一版主合同。下载后在本机修改，再在同一合同内“上传修改版本”，即使旧稿没有系统内人工复核记录也会对比。连续多次修改以直接上一版为基准，不跳过中间稿去匹配更早的复核稿；其他合同、补充材料及签署件不作为该基准。
- 正文按顺序比较，保存新增、删除、修改范围和双方原始版本／段落锚点，处理重复段落及编号变化；长文按差异范围成对分片，避免先读完整新稿再读旧稿导致模型失去对照。完整文本均参与提炼。差异过大时保留全部文本并标记范围对比，不假设逐条对应；段落移动可能体现为新增及删除。
- 旧稿未提取正文时走原有解析／格式转换。没有旧稿或旧稿无法读取时明确标记不可对照，仅根据可用确认稿整理。修改原因缺少记录时要求提案标注“修改原因待确认”，不从文本差异推断法务动机，也不把被删除内容视为最终认可。
- 经验列表和合同详情的“查看修改前后对比”分页展示双方文本及原件下载。`GET /learning-tasks/:id/changes?offset=0&limit=20` 沿用合同权限；列表不返回整个来源正文。对比依据是识别出的正文，图片、排版、未识别内容需核对原件。
- 单提案需精确版本／段落引用或真实人工处理记录；校验目标技能、规则及依赖。沿用模型 JSON 校验、最多两次输出纠正及最多三次网络尝试。单任务超过 50 条提案失败，不静默截断。
- 同一任务同一包的多条建议合并到一份草稿；revision、正式父版本及锁防止覆盖并发修改。已被改写的同一目标须人工合并或重新整理。
- 预审创建时冻结所有已发布技能候选；分类后只匹配通用及该类型的已发布技能，同时核对规则依赖。请求、断点缓存、报告绑定内容及版本；旧任务缺少技能快照时按空列表处理。
- 依赖使用精确规则版本 ID。其规则被后续版本替换后，旧技能不进入新任务，须基于新规则重新核对、生成并发布新技能版本；旧排队任务仍按自己的旧快照执行。
- 评测创建时固定已发布技能和规则候选，分类后同样匹配并记录；技能草稿首版不单独参与评测，正式发布后可用现有评测入口验证。

## 接口与入口

接口均位于 `/api`，写操作需会话及 CSRF；具体 schema 见 `docs/openapi.json`。

| 接口 | 用途 / 权限 |
|---|---|
| `GET /skill-packs` | 全部技能版本；legal、publisher 或 admin |
| `POST /skill-packs/:id/versions` | 建草稿，`baseVersionId` 固定父版；publisher 或 admin |
| `PUT /skill-pack-versions/:id` | 编辑草稿，需 `revision`；来源与依赖由服务端保留 |
| `POST /skill-pack-versions/:id/submit、publish、retire` | 提交、发布、停用；发布通用包需 `commonConfirmed:true` |
| `GET /skill-pack-versions/:id/export、sources` | Markdown、按合同访问权限过滤的来源关联 |
| `GET/PUT /learning-settings` | 查询开关；管理员更新需 `updatedAt`，初始为 null |
| `GET /learning-tasks?contractId=…` | 最近 100 条任务及可访问来源语境 |
| `POST /learning-tasks/:id/retry` | 非运行态任务重新整理，需 `revision` |
| `PUT /learning-tasks/:id/proposals/:proposalId` | 编辑待确认内容，保留来源及依赖，需 `revision` |
| `POST /learning-tasks/:id/proposals/:proposalId/adopt、ignore` | 采纳为草稿或忽略，需 `revision`；采纳需 publisher/admin |
| `GET /review-plan`、`GET /reviews/:id`、报告 | 增加 `skillPacks` / `snapshot.skills`，保留旧字段 |

固定技能包编号为 `review-skill-common` 或 `review-skill-{typeId}`。模型 `review(document, rules, knowledge, background, trace, batchStore, skillPacks)` 新增第七个可选参数，旧调用默认空数组。提炼方法为 `distill(input, trace, validate)`；没有 Codex 运行时或命令执行能力。

后端主入口：`skills.js`、`learning.js`、`workflow.js`、`model.js`、`queue.js`。前端：`SkillPacks.vue`、`LearningTasks.vue`，分别嵌入规则中心、反馈中心及合同详情。技能来源关联与可复用正文分开，来源原文不写进技能模型请求。

## 验证及能力边界

- `backend/test/skills-learning.test.js`：范围、状态、依赖、证据、脱敏、段落变化、技能请求及缓存隔离。
- `backend/test/offline-changes.test.js`：新增／删除／修改、重复段落、长文成对分片、版本引用、分页和无旧稿。
- `backend/test/integration/offline-learning.test.js`：真实 HTTP 上传、下载、本机修改同名再上传、最终结论、两稿学习、技能采纳发布及后续复用的独立测试库闭环；旧稿无需人工复核，跨合同来源被隔离。
- `backend/test/integration/skills-learning.test.js`：空库和开关、事务去重、三种结论、编辑采纳发布、下次审核加载、排队和重试快照、评测、规则依赖、并发冲突、失败重试、祖先稿、通用确认、无新增经验及访问权限。每次独立建库、销毁。
- `scripts/skills-ui-qa.cjs`：真实 Edge、独立数据库、确定性提炼适配器，验证页面闭环、版本复制编辑、Markdown、详情状态及窄屏。需 Playwright runtime 的 `NODE_PATH`。
- `scripts/skills-model-smoke.cjs`：真实已配置模型、完全虚构的人工修正与附条件结论、独立数据库。临时发布只发生在验收库，完成后删除验收库，不往正式技能库预生成内容。可用 `SKILL_SMOKE_ADMIN_DATABASE_URL` 提供仅用于建验收库的连接；输出不含密钥。
- 模型调用和技能版本正确不证明法律质量改善。当前验证不含法务独立标注验收，不承诺语义去重、复杂 Word 差异对应或完全自动脱敏。机械校验覆盖已知主体／标题／编号、常见公司名称、邮箱及手机号；发布前仍须人工检查商业秘密和个案细节。
- 首版每包最多 20 条、正文合计 24,000 字符；提炼按 16,000 字符分片。没有自动把全部经验升级为通用技能，没有历史合同批量回填，没有自动重写正式规则或合同正文。

## 发布与回退

先完成已授权的备份及迁移，以默认关闭状态部署。验收空库及真实模型合成样本闭环后，再开启自动整理。仅之后新确认的合同产生任务。

回退顺序：关闭 `contract_learning` → 停 Worker/API → 原子恢复前版应用指针 → 重启服务。保留技能和经验表，迁移 down 主动拒绝删表；恢复旧应用不等于恢复数据库备份。需要恢复备份时，应先另行验证目标和恢复范围。服务器密钥、账号密码及模型密钥只留在现有私有配置中，不写进交接文件。
