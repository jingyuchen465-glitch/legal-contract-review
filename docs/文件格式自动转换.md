# 文件接入与自动转换

手动提交、修改版本、补充材料、签署件及钉钉收件统一接受以下格式，每份原件不超过 50MB：

| 来源格式 | 预审内容 | 转换副本 |
|---|---|---|
| PDF | 原有 PDF 文本及 OCR 页坐标 | 保持原件 |
| DOCX | 原有段落、表格及修订视图 | 保持原件 |
| DOC、ODT | 自动转 DOCX，再提取段落及表格 | DOCX、PDF、结构化 JSON |
| XLS、XLSX、CSV、ODS | 工作表、单元格地址、值、公式及显示格式 | PDF、结构化 JSON |
| PPT、PPTX、ODP | PDF 页文本及坐标，附加对应页的演讲者备注 | PDF、结构化 JSON |

原件的文件名、字节、SHA-256、版本编号和下载入口保持不变。副本写入该版本的独立目录，与原件一起纳入现有备份。转换副本与原件使用同一合同权限及限时版本凭证。DOC/ODT 转换完成后也可使用原有在线编辑及批注下载；在线编辑保存为新的 DOCX 版本。

## 用户操作

直接上传原文件，不必手工另存。页面依次显示「等待自动转换」「正在自动转换」「已自动转换」，随后继续原有预审。转换完成后可查看或下载 PDF 版式、DOCX 副本及提取内容。

转换失败时原件仍可下载。主合同点击「正式重新预审」重试；补充材料和签署件点击「重试转换」。加密、损坏、内容与扩展名不符、过大的文件会有具体提示。未配置转换器时 PDF/DOCX 仍按原流程处理，其他受支持格式先保存并记录转换失败原因。

引导式预分析的主合同、补充材料、签署件均使用独立转换队列。AI 预分析通道繁忙时，后续文件仍能完成转换及正文提取；转换完成后等待 AI 属于另一个阶段。补充材料、签署件不替换当前审查版本，不自动参与主合同的条款审查。钉钉收件继续按原附件内容哈希去重；同名附件更新会产生新原件版本。

## 转换器部署

转换器为独立 Python + LibreOffice 服务。主 API 只保存和校验上传文件，Worker 调用转换器，不在 HTTP 上传事务中运行 Office 程序。

### Docker

在 `.env` 设置独立的随机凭据（至少 32 位）：

```dotenv
CONVERTER_TOKEN=填写至少32位随机值
CONVERTER_TIMEOUT_MS=300000
```

```powershell
docker compose up -d --build converter api worker
```

Compose 自动设置 `CONVERTER_URL=http://converter:8091`。API 启动时运行新增的版本元数据迁移。转换器不映射宿主机端口，仅加入内部网络，使用只读根文件系统、临时目录和资源限制，不挂载合同存储目录。

### 本机 Windows 开发

```powershell
winget install --id TheDocumentFoundation.LibreOffice --exact --source winget --silent --accept-package-agreements --accept-source-agreements
python -m venv .local/converter-venv
.\.local\converter-venv\Scripts\python.exe -m pip install -r converter/requirements.txt
```

在 `.env` 中添加：

```dotenv
CONVERTER_URL=http://127.0.0.1:8091
CONVERTER_TOKEN=填写至少32位随机值
# 非默认安装位置时设置
# SOFFICE_PATH=C:/Program Files/LibreOffice/program/soffice.com
```

```powershell
npm run db:migrate
npm run dev
```

`npm run dev` 先检查数据库连接，再检查转换器健康；配置本机 8091 地址且服务尚未运行时自动启动转换器，最多等待 30 秒。已健康的服务直接复用。数据库不可达、转换引擎未就绪或启动超时时会停止启动，并明确提示原因；不会先让 Worker 消费待办。也可单独运行：

```powershell
# 单独运行时需把 CONVERTER_TOKEN 放入当前进程环境；uvicorn 不自动加载 .env
.\.local\converter-venv\Scripts\python.exe -m uvicorn app:app --app-dir converter --host 127.0.0.1 --port 8091 --no-access-log
```

可选 `CONVERTER_PYTHON` 指定其他已安装所需依赖的 Python。管理员配置页提供转换引擎配置和健康检查，`GET /health` 仅检查引擎是否安装；真实格式转换以样本测试为准。

## 内容边界

- Excel 提取全部工作表及隐藏行列，不受打印区域限制。保留公式及缓存值，不由 AI 推算缺失缓存；XLS/ODS 规范化时可能重算公式，需要人工核对。日期使用明确的日期值，金额同时保留显示格式；图表、图片和嵌入对象需核对原件。
- CSV 接受 UTF-8（含 BOM）及 GB18030，支持逗号、分号或制表符分隔。以等号开头的文本作为原文保留，不执行公式。
- PPT 包含隐藏页及演讲者备注。正文图片按现有 PDF/OCR 机制处理，需部署 OCR 服务；备注按页关联，不伪造图形坐标。
- 所有转换文件都增加人工核查项，最终结论仍遵循原有法务复核门槛。转换只解决文档接入，不自动为任意业务类型发布审查规则。
- 不支持 XLSM、DOCM、PPTM、压缩包等未列出的格式。Office 引擎禁用宏及活动嵌入内容，关闭自动链接更新；生产转换容器无外网出口。
- 文件解压总量不超过 150MB；表格所有工作表的矩形范围合计不超过 100,000 个单元格，提取文本不超过 5M 字符。过大或过于稀疏的文件需拆分。单次 Office 子进程超时 90 秒，客户端含排队等待默认最多 300 秒。超时会终止该任务的进程树，不使用系统全局 Office 进程清理。

## 验证

```powershell
npm test
npm run test:integration
npm run build
.\.local\converter-venv\Scripts\python.exe -m pip install -r converter/requirements-test.txt
.\.local\converter-venv\Scripts\python.exe -m unittest discover -s converter -p 'test_*.py' -v
```

Node 测试覆盖真实容器校验、原件字节及哈希、转换失败重试、副本访问权限、隐藏单元格及公式锚点、补充材料/签署件独立任务、钉钉新格式收件。Python 测试实际运行 LibreOffice，覆盖 DOC、XLS、XLSX、CSV、PPT、PPTX、ODT、ODS、ODP、隐藏页、备注、隐藏工作表和打印区域外内容；未安装 LibreOffice 时明确跳过该组实转换测试。
