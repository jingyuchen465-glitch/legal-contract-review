# 修改复核与审查收敛

本次修改针对“采纳建议、保存新稿后重新全审，意见不断变化”的问题。代码已在本地实现，本文不代表已部署正式站点。

保存新稿、补充材料或主动重新审查时，沿当前合同版本的实际父链寻找最近一次已完成的 Agent 报告作为复核基线。同一份合同连续保存多个尚未审完的中间稿，仍使用最近的完整报告；不使用未完成报告或其他分支的报告。首次审查保持原流程。

基线冻结上轮问题、法务认可/驳回/修正及理由、用户已提供的背景、已解决记录和原材料清单。已解决与已驳回问题会继续传给下一次复核，避免从当前风险列表移除后被重新当作新问题。历史报告与最终法务结论不覆盖。

审查仍读取全部当前材料，额外读取 `read_revision_baseline` 的分页数据，获得上轮记录与正文增删对照。正文比较使用段落文本，保留日期、金额、标点和内部空格；Word 包内元数据变化、段落编号变化不等于正文风险变化。无法比较时明确标记，不能声称修改引入风险。材料访问权限覆盖复核基线；无法读取的旧材料不作为新任务基线。

提交报告时，`revisionReview` 必须绑定固定基线报告，逐项交代已解决、部分解决、未解决、保留法务处理或待核实。已解决项需当前版本逐字原文；删除条款或适用范围变化导致无原文时，需说明解决方式并确有材料或背景变化。认可 AI 建议不代表正文已修改，也不代表接受风险。

每条当前风险或待确认意见须关联上轮问题，或说明新增原因：修改引入、上轮漏检、材料或背景变化、判断修正。相同的上轮问题允许合并到一条当前意见。法务已驳回或先前已解决的问题再次提出时，必须说明重新提出的事实或依据。不能用更换措辞、遗漏旧问题或未变正文上的漏检冒充改稿进展。

全部问题解决后允许 `findings=[]` 并结束复核。是否解决、是否遗漏实质风险仍取决于模型判断和人工核验，结构与证据校验不等于法律质量保证。保存文件仍保留版本记录，本次未合并文件版本或取消全文阅读。

工作台和历史报告增加修改复核区，展示旧问题状态、法务理由、新增原因及当前原文定位。HTML 报告与通用报告数据保留同一对照记录。历史报告缺少新字段时继续正常显示。无需数据库迁移；已有任务不回写基线，下一次保存或重新审查时生效。

验证入口：

- `npm test`：基础与 Agent 单元回归。
- `node scripts/test-agent.mjs backend/test/integration/*.test.js`：临时数据库中的完整集成回归，包含保存回调、Office 改稿、附件分组、权限及官方 Harness 子进程。
- `npm run build`：前端构建。
- `node scripts/revision-review-ui-qa.cjs`：虚构数据的真实浏览器回归，覆盖对照展示、零风险结束、原文定位、历史兼容和手机布局；结果与截图在 `.local/revision-review-qa/`。

基础回归使用模拟审查输出及虚构网关，验证业务约束与执行链路。后续已用一份虚构采购合同完成真实模型三轮本地验收：首轮1项交期问题，修改后已解决、无新增，正文未变再次审查仍维持已解决，详见[本地法务验收记录](修改复核本地法务验收-20261110.md)。这不是跨合同、跨模型的一致性评测；真实 OnlyOffice 编辑服务仍未在本次覆盖。部署时需更新后端、重启 API 与 Worker 并发布前端构建产物，无需重建固定 Harness 源码运行时。
