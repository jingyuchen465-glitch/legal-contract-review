# 模型流式请求超时优化

状态：代码及工程验证完成。发布包基于页边审阅上线后的正式版本制作，实际发布及公网验证记录保存在 `.local/model-timeout-deploy/`。

## 问题及行为

正式日志核实 13 次生成完整 `submit_review` 报告期间的超时：模型在中止前约一秒仍有内容输出，却被单次请求 300 秒的总时限定时器断开。重试重新生成整份报告，造成重复等待。诊断证据保存在 `.local/model-timeout-audit/`。

新实现将原来的一个定时器改为三个独立边界：

| 边界 | 默认时限 | 计时含义 |
| --- | --- | --- |
| 首次实际内容 | 300 秒 | 请求开始后，等待生成的正文、推理片段或工具调用参数；收到 HTTP 头或心跳不算开始生成 |
| 输出停滞 | 120 秒 | 开始生成后，每次有新内容都刷新；只有连续无内容达到该时限才暂停 |
| 单次请求总时长 | 900 秒 | 持续生成也不能无限占用请求；整轮仍受既有的默认 30 分钟任务预算约束 |

SSE 在转发时增量解析，支持跨网络分片的 UTF-8、CRLF 和工具调用参数；不保存额外的模型正文。心跳、空内容、单纯角色/用量事件、纯空白与无效 JSON 不刷新内容计时，未完成的单事件解析内存限制为 1 MiB。总时长上限继续防止无限输出。

配置项分别是 `MODEL_REVIEW_TIMEOUT_MS`、`MODEL_REVIEW_IDLE_TIMEOUT_MS`、`MODEL_REVIEW_MAX_DURATION_MS`。普通模型调用和退役分批引擎不改为此策略。SDK 自身的兜底等待晚于本应用总时限，避免先以笼统错误切断请求。单次自动重试策略保持一次；用户停止、运行时关闭及调用端断开会关闭对应上游请求并清理计时器。

## 记录与页面

失败事件分别记录 `first_response_timeout`、`stream_idle_timeout`、`request_deadline` 或 `connection`，附带对应时限、总耗时、最后内容进展和实际停滞时长。`timeoutMs` 在失败事件中表示实际触发的时限，而非混用总耗时。HTTP 错误仍单独分类。

首次内容及之后至多每 10 秒保存一次 `model_progress`，完整响应保存 `model_response`。事件仅含数字计时、字节数和固定文案，不含合同正文、推理内容或凭据。自动评审接口返回这些事件，页面显示“正在生成审查内容”，展示停滞时限及最大总时长，完整响应结束等待状态。收到内容不等于提交报告，报告与复核校验仍须成功。旧轮次及历史诊断的显示保持兼容。

## 验证

- 修改前运行真实 SDK/HTTP 回归测试，持续输出超过缩短后的初始时限即失败；修改后完整接收，随后增强为分片生成 `submit_review` JSON，验证工具只在完整参数到达后执行、只发一次请求且没有失败事件。
- 137 项单元测试通过，包含计时分类、持续输出上限、清理计时器、SSE 分片/心跳、页面新旧诊断与生成状态。
- Agent 与自动评审 46 项集成测试通过。真实 SDK 子进程及本机 HTTP 覆盖心跳空转、内容停滞、总上限、传输断开、一次重试和取消后上游连接关闭；增强后的报告参数流场景单独复测通过。
- 浏览器覆盖自动轮询、重试、生成状态、完整响应结束等待、桌面与手机布局；无未处理页面异常。既有方法列表场景根据接口实际方法数断言，兼容新增的必读系统方法。
- 前端生产构建通过。

正式发布候选包另在干净的线上源码基线上验证：133 项单元测试、48 项集成场景（包含页边审阅浏览器保存与导出）、7 个自动评审浏览器场景的 23 项检查通过，前端生产构建通过。未发布的系统技能修改未包含在本包内。

以上工程验证使用本机模拟模型和隔离数据库，没有调用真实付费模型，也没有自动继续任何线上暂停任务。整份报告仍在工具参数完整后提交；真正断连时尚未提交的报告仍需要重新生成。本次解决持续输出被原 300 秒总时限切断的问题，不宣称模型速度或上游网关限制已改善。
