# 页边批注与修订：本地实现与验收

本地入口：`http://localhost:8080/#/review-preview`。正式合同页面的“页边批注与修订”按钮使用同一工作区；右上角 `···` 可打开原 ONLYOFFICE 入口。本次未发布或部署。

## 实现范围

- 左侧加载真实 DOCX，右侧在同一个滚动面中显示橙色原生批注、紫色修订卡片与正文连接线，替代编辑时原有的独立意见侧栏。
- 批注与修订目录来自编辑器公共 API。位置来自 `ui.viewport.getRect`；替换修订缺少实体坐标时，使用其真实段落导航地址的首字符定位。坐标不可解析时不伪造连线。页面挂载、滚动、缩放及卡片展开后重新排布，避免卡片相互遮挡。
- 选中文字后新增批注、回复、完成批注；修订卡片接受或拒绝；正文键盘输入自动记录作者修订；撤销、重做和修改前后对照。
- DOCX 导出显式保留 comments 与 review-preserving tracked changes。保存前记录文档版本，成功后仅把该版本标为已保存，期间的新修改继续保持未保存状态。
- 本地示例保存在浏览器 IndexedDB；实际合同保存走权限、CSRF、文件解析校验和合同锁，产生不可变新版本及审计记录。已有新版本时返回 409，页面仍保留修改。
- 原件和已完成报告不会被就地覆盖。原 ONLYOFFICE 集成继续保留。

主要文件：`frontend/src/pilot/WordReviewWorkspace.vue`、`ReviewMarginRail.vue`、`word-review.css`、`backend/pilot/word-review.js`。

## 本地运行

```powershell
npm run db:local
npm run db:migrate
node backend/index.js
node scripts/prepare-margin-review.cjs
npm run dev --workspace frontend -- --host 127.0.0.1
```

示例来自仓库内的虚构仓储合同，生成 10 条原生批注和 2 组正文替换修订，不调用模型。示例只由 Vite 开发中间件提供，开发预览路由不进入生产构建。

## 验收结果

2026-11-11 在本机 Microsoft Edge / Playwright 验证：

1. DOCX 导出保留 10 条批注、2 个插入与 2 个删除。
2. 滚动 120px 后卡片同步移动 120px，80% 与 100% 缩放后继续绑定正文。
3. 点击页边批注与修订可定位正文，编辑器公共活动 ID 随之变化。
4. 接受迁仓修订、拒绝付款修订后，检查导出 DOCX 的 OOXML：迁仓正文采用修改稿，付款正文恢复原稿，两组修订标签消失。
5. 保存到 IndexedDB 后真正重载页面，恢复已保存的 DOCX。
6. 鼠标定位并用 Home / Shift+End 真实选字后，新增批注写入 `word/comments.xml`。
7. 回复内容保留在导出评论中。
8. 真实键盘输入产生 `法务审阅人` 署名的 `<w:ins>`；撤销后恢复。
9. 模拟存储写入失败，正文及批注保留，状态仍为“有修改待保存”。
10. 修改后正文与修订视图切换成功；浏览器无未捕获错误。

## 使用边界

- 本版编辑引擎为 `superdoc@2.30.0`，并非 WPS 或 ONLYOFFICE 皮肤。SuperDoc 外层为 AGPL / 商业双许可，`@superdoc/docx-engine@0.29.0` 为单独专有许可，完整说明见《依赖、许可与上游登记》。当前用途是本地开发评估；不能称作完整开源 WPS 替代品。
- 编辑器仍存在中文混排差异：示例中的部分条款编号会单独折行；复杂合同版式需要用真实模板进一步验收。当前未声称与桌面 WPS 像素一致。
- 原生“接受修订”“完成批注”改变文档内容及批注状态；工作台“认可/驳回审查意见”、审批流程结论仍使用原有业务操作，两者不会互相冒充。
- 浏览器示例保存仅限当前浏览器与站点；实际合同应使用工作台的新版本保存或导出 DOCX。签章、手写批示、不可篡改审批流水不在本次范围。
- 编辑器资源较大（约 21 MB，gzip 约 9 MB），已从工作台首页拆开，首次打开仍需要加载。当前只验收本机环境，未做生产网络与复杂长文档性能验收。
