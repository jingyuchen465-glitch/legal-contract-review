## 3. 已复现的问题

### BUG-001：切回 v1 后意见显示为零

操作：打开上述线上合同，将“当前材料”从 v2 切到 v1，查看审查意见和报告选择器。

实际：v1 对应两份已完成报告，其中一份接口返回 **7 条 finding、13 条 evidence**，页面却显示 **0 条意见**，且没有可用的报告选择器。顶部仍显示当前 v2 的“已取消／继续审查”。本地最小场景也复现：数据库有 1 份 v1 完成报告，页面 finding 为 0、报告选择器为 0。

预期：查看 v1 时能选择、查看 v1 的完成报告；历史材料与当前工作任务的状态需要清晰区分。

根因：`frontend/src/pilot/AgentReview.vue` 的 `reports` 固定按 `contract.current_version_id` 筛选，`refresh()` 也固定读取该版本的会话；`switchFile()` 只改变 `selectedVersion`，没有改变报告／会话选择。缺失的是页面展示，并非数据库中的报告。

线上复现命令已执行且返回非零退出码：

```text
node .local/bug-audit/matt-v1-switch.cjs
BUG_REPRODUCED: completed v1 report exists in API but UI shows 0 opinions after switching to v1
```

证据：`.local/bug-audit/matt-v1-switch-result.json`、`.local/bug-audit-v1.png`；本地场景为 `v1-report-missing-local`。

### BUG-002：历史文件的改稿入口静默打开最新版

操作：准备 v1、v2 两份不同正文，v1 已有报告，当前版本为尚未完成预审的 v2；在页面选 v1，再点“打开改稿”。

实际：创建的 `la_editor_sessions.version_id` 是 **v2**，编辑器配置标题为 v2 的“双方谈判后新稿.docx”。此前查看的材料是 v1，操作时没有明确提示正在切到 v2。

预期：历史文件应有明确的只读或编辑规则；若只能编辑当前版本，需要显式提示并同步材料选择，不能让法务误以为在改 v1。

根因：`OfficeWorkspace.vue` 的编辑器请求只传可选 `reviewId`，不传所选 `sourceVersion.id`；`backend/pilot/office.js` 始终读取 `contract.current_version_id`。本场景前端没有选中旧报告，因此请求不带 `reviewId`，后端直接打开当前 v2。若指定不属于当前版本的报告，后端另有 409 校验，但这没有保护上述无报告场景。

证据：`legal-flows-results.json` 中的 `historical-editor`；对应截图 `.local/bug-audit/historical-editor.png`。

### BUG-003：生成批注建议稿绕过未保存编辑

操作：在有完成报告的合同中打开改稿，编辑器发出有修改事件，页面显示“有修改待保存”；点击工具栏“生成批注建议稿”。

实际：批注接口返回 201，**保存请求次数为 0**，编辑区消失，并调用 `destroyEditor()`。生成文件使用报告绑定版本的已存储正文。

预期：先完成保存并核验版本；保存失败或保存期间仍有新输入时保留编辑器。若保存后报告成为历史报告，也不能直接用旧正文生成最新稿，须一并处理 BUG-005。

根因：`AgentReview.vue` 的 `generateAnnotatedVersion()` 直接 POST，然后 `editor=false`；没有调用编辑器已有的 `saveForNavigation()`。其他离开编辑器路径上的保存保护没有覆盖该入口。

验证边界：实测使用 DocsAPI 替身发出 OnlyOffice 的真实事件形状，验证了工作台的保存请求和关闭行为；没有在生产 OnlyOffice 中输入真实合同内容，**不据此声称已证明生产手工文字永久丢失**。已经证实的行为存在遗漏未保存修改的风险。

证据：`dirty-annotated` 记录为 `saveRequests:0`、`editorClosed:true`、`editorDestroyed:true`；截图 `.local/bug-audit/dirty-annotated.png`。

### BUG-004：成功生成后仍提示 JavaScript 错误

操作：有已完成报告时点击“生成批注建议稿”。

实际：接口返回 201，数据库已产生新版本且更新当前指针；页面同时显示 `ElMessage is not defined`。本次操作的正常刷新被异常跳过，材料选择一度为空；后续三秒定时刷新可能恢复，不能说页面永远无法恢复。

预期：只显示成功反馈，及时显示生成的新版本。

根因：`AgentReview.vue` 调用 `ElMessage.success()`，却没有导入 `ElMessage`。异常被 `operation()` 捕获，在执行正常 `refresh()` 前转入错误处理。

影响：法务难以判断是否生成成功，容易重复点击、刷新或误认为保存失败。

证据：`annotation-success-error` 记录及同名截图。

### BUG-005：旧报告生成新稿会回退最新正文

操作：v1 正文为“交付期限另行商议”，生成 v1 报告；再保存正文为“交付期限已明确为三十日”的 v2。调用 v1 报告的 `POST /api/reviews/:id/annotated-version`。

实际：返回 201，新建 **v3**，其 `parent_id` 指向 **v2**，同时把合同当前版本切到 v3；但解包生成 DOCX 后，正文是 **v1 的“交付期限另行商议”**，不包含 v2 已谈妥的“三十日”。

预期：历史报告可以导出对应旧文件；若要将其生成物设为当前稿，必须有明确的历史分支／替换语义及校验，不能静默把旧正文接在当前版本后面。

根因：`backend/pilot/annotated-versions.js` 从 `run.version_id` 读取源文件，但 `createAnnotatedVersion()` 不检查它与当前版本是否一致；随后 `contracts.js:addVersion()` 总以当前版本为 parent 并更新当前指针。已有相同摘要的 artifact 时可能直接返回旧产物，本次最小复现使用首次生成，证实新建路径的问题。

触达边界：本项通过本地真实 API 复现；**没有在生产合同上执行**。当前主界面的历史报告选择还受到 BUG-001 限制，因此不将这个 API 复现写成已在线上普通点击复现。修复历史报告展示时必须同时防止这个路径被直接开放。

证据：`old-report-new-version` 记录，含 `http:201`、v2 parent 和 v1 生成正文。

### BUG-006：应用改稿后，生成建议稿按钮无响应

操作：打开改稿 → “生成完整条款改稿” → 核对预览 → “应用改稿并保留修订” → 等待页面正常轮询更新 → 再点工具栏“生成批注建议稿”。

实际：应用步骤成功创建 v2，DOCX 解析文本为“乙方应在合同生效后三十日内完成交付”；没有自动采纳 finding。编辑区仍保留 v1 历史意见供核对，此时生成建议稿按钮**可点击**，但点击后 `annotated-version` 请求为 **0 次**，没有操作反馈。

预期：按钮对应明确的可用操作；若需等待当前版本重新审查，应禁用／隐藏并提示原因。

根因：父组件轮询发现当前 v2 无完成报告后把 `run` 清空；子组件的 `review` 仍回退使用打开时的 v1 `snapshot`，所以工具栏按钮继续显示。事件到达父组件后，`generateAnnotatedVersion()` 因 `run` 为空直接返回。

这里确认的是**父子组件操作状态不同步**。保留历史意见本身有核对用途，不认定为 bug；也撤回早期临时笔记里“编辑器打开时切换报告导致快照不更新”的确定性结论，因为现有编辑模式隐藏了报告选择器，该操作路径并未实测成立。

证据：`post-apply-annotation-noop`，`buttonEnabled:true`、`annotationRequests:0`；同名截图。

## 5. 已验证正常及未覆盖范围

- 保存接口失败时，编辑器保留，未创建新版本，不会直接返回旁批。
- 保存请求处理中又收到新修改事件时，真实签名 callback 成功保存 v2，工作台仍保持待保存状态并要求再保存，编辑器未关闭。
- 本轮真实 UI 已走通生成完整条款预览、应用、创建新版本及重新打开；finding 的 disposition 仍为 null，应用改稿没有擅自表示法务采纳。
- 原有 Office 集成用例通过，覆盖原文件不变、修订标记、签名 callback、正文或复核意见变化后的旧 token 失效等。
- 本地使用真实生产前端构建、真实应用路由、真实数据库和 DOCX 处理；模型条款响应与 DocsAPI 为本地替身，不验证模型质量、OnlyOffice 内部排版、实际键盘输入同步或跨标签页冲突。以上结果不能替代这些专项验证。

## 7. 建议修复顺序

1. 先统一“查看版本、报告版本、编辑版本”的校验，限制历史建议稿更新当前指针，处理 BUG-002、005。
2. 为生成建议稿补保存保护，并在保存改变版本后检查报告适用性，处理 BUG-003。
3. 修复历史报告／会话选择和父子组件按钮状态，处理 BUG-001、006；不要直接开放未经校验的历史稿写入入口。
4. 补 `ElMessage` 导入并确保成功操作刷新，处理 BUG-004。
5. 隔离处理退役服务语法错误，明确其是否保留。
