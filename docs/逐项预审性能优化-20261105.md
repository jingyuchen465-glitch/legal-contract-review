# 逐项预审性能优化（2026-11-05）

本文记录第一阶段的并发优化。当前完整实现还包括按请求预算优先读取完整合同、每批 8 项及精简符合项输出，见[完整合同分批审查优化](完整合同分批审查优化-20261105.md)。

本轮已完成本地实现和验证，尚未部署。线上正在执行的任务没有被取消或重启。

## 定位依据

北京时间 16:14–16:15 只读核对线上任务：51 个审查点，每批 5 项，共 11 批；正文分为 3 段，技能分组为 1 组，合计 33 次模型请求。前三次耗时 201.262、82.422、155.847 秒，均为第一次输出即通过，任务并发配置为 1。原代码在嵌套循环内等待每批返回，因此单个合同始终串行。80 分钟是按前三次响应时间外推的估算，并非最终实际耗时。

原进度进入逐项审查即为 55%，完成批次只映射到 55%–85%。57% 实际仅完成 2/33 批。此百分比不代表耗时比例。

## 实现

- 新增 `MODEL_REVIEW_CONCURRENCY=3`，有效范围 1–8，非法值回退到 3。与 `MODEL_CONCURRENCY` 的任务并发分开。每个 Worker 进程内所有普通逐项审查请求共用上限，覆盖不同网关实例及请求重试；多 Worker 进程分别拥有自己的预算。
- 每个预审使用有界工作池，按原顺序保存返回结果，防止乱序返回改变意见选择和证据合并顺序。请求内容、每批 5 项、正文分片、模型、提示词和引用校验保持原逻辑。
- 任一批次最终失败即停止派发后续工作，并等待已启动工作结束，再由流程记录失败。已完成有效批次仍写断点；原输入的缓存键不变。排队请求发送前及每次网络重试前检查取消状态与固定模型配置。已发出的 HTTP 请求仍等待响应或现有超时，取消后不能保存其结果。
- 记录批次计划、实际完成批数和总批数。进度按完成数量计算，包含技能分组，数据库百分比更新保持单调。前端逐项审查阶段显示“已完成 X/Y 批”、已用时间及粗略剩余时间，兼容旧任务没有计划记录的情形。剩余时间依实际吞吐估算，至少有 3 个非缓存批次后才展示；限流、重试和模型速度变化会影响估算。

## 验证

- 修改前运行 `node --test backend/test/review-performance.test.js`：并发测试失败（峰值并发 1，预期 2），证明回归能识别串行问题。
- `npm test`：117 项通过。
- `npm run test:integration`：138 项中 136 项通过，2 项既有浏览器测试跳过，无失败。更新了旧测试对串行日志顺序及总请求次数的假设，继续检查全部批次覆盖、有效批次不重复以及失败批次最多纠正两次。
- `npm run build`：通过。
- `node scripts/review-progress-ui-qa.cjs`：真实 Edge、生产构建、本地 API 替身，覆盖桌面、390 像素宽度、旧记录和尚无估算时的显示。输出 `.local/review-performance/{desktop.png,mobile.png,ui-result.json}`。未调用真实模型或写线上业务记录。
- `node scripts/review-performance-benchmark.cjs`：模拟每次请求 50 毫秒，51 个规则、3 段正文、33 次请求。串行 2020 毫秒，3 路并发 657 毫秒，约 3.07 倍；返回结果及覆盖信息完全一致。这只验证调度收益，不证明真实模型响应速度或法律建议质量。

浏览器脚本使用工作区提供的 Playwright 包；需要把对应依赖目录加入 `NODE_PATH`，无需新增项目依赖。

## 发布与后续评估

没有数据库迁移或新增依赖。部署时须包含新的 `backend/pilot/review-execution.js`、`frontend/src/pilot/ReviewProgress.vue` 和 `frontend/src/pilot/review-progress.mjs`，以及本轮修改的网关、配置、断点、工作流和 Review 页面，重新构建前端。应在当前线上版本上应用这次增量，避免用本机全部未提交修改覆盖其他会话已上线的工作。

正在运行的任务继续使用原 Worker 代码。切换 Worker 应先等待任务完成，或使用既有恢复机制从断点继续，不能通过新建预审替代恢复，否则会失去原任务的断点。若模型服务出现更高频率的 429 或响应退化，将新参数调回 1 并重启 Worker；该调整不改变已固定的规则和模型快照。

在服务端允许 3 路并发且单次响应速度相同的前提下，原先约 80 分钟的估算有望降至约 30 分钟，真实耗时须上线后核对。请求次数及审查范围本轮没有减少；下一阶段可针对长上下文、批大小或更快模型做有独立法务标注的对照评估，再决定是否采用，不能直接将全部内容压成一次输出并假定质量不变。
