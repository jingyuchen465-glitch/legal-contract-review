# 审查校验与内容复核边界修复

2026-11-12。本地实现与验证记录；尚未发布到正式站点。

线上任务的首次报告已在 `edits[].newText` 提供完整修改正文，但提交代码只用正则检查 `suggestion`，将短说明判为没有正文。之后单文件内正文与附件的冲突又被要求引用两个不同文件版本。报告每次遇到第一个错误即停止检查，造成整份报告多轮重写。原始诊断保存在本机 `.local/review-latency-audit.json` 和 `.local/review-submissions-audit.json`，仅含运行摘要及结构化提交内容摘录，不用于证明法律质量。

本次按审查、改稿、报告兼容、导出整条流程处理，不增加合同类型、主体称谓或此次合同专用例外。

- 删除 `agent/schemas.js` 的 `hasUsableClause` 和 `clause-drafts.js` 的 `hasClauseWording`。报告和旧报告兼容校验不再依赖“条款正文”“替换为”、甲乙方称谓、特定语言或最少句长。
- 删除改稿验证中根据句首词判断内容合格性的正则。条款含义、正文是否可直接使用、未知条件是否妥善处理，由生成 Agent 按系统技能复核。自动评审仍须保存候选报告并通过 `observe_review` 记录复核，程序不假称进行了独立模型法律评审。
- 风险项保留非空处理建议或结构化改稿的存在性检查。正文可以只放在 `edits.newText`，`suggestion` 可为短说明或留空；删除用 `operation=delete` 和空 `newText`。
- 保留版本范围、逐字原文、段落对应、全文读取覆盖、法律来源、权限、复核基线及人工结论保护。改稿继续校验操作枚举、原文锚点、非空新增/替换、空删除、重复目标、实际变化、自动编号及 Word 复杂结构。普通审查和自动审查共用 `report-edits.js`，不能通过切换入口绕过这些校验。
- 新增 `validation-issues.js`，收集独立检查发现的错误，返回 `issues:[{path,code,message}]`。路径包含意见和改稿下标，跨文件改稿也保留原始下标；运行时、数据库及取消错误继续直接抛出。结构格式检查仍先执行，依赖关系缺失时先补齐其前提；并非承诺一次发现所有语义或法律问题。
- 向模型提供的提交工具 JSON Schema 从实际 Zod 接收协议生成，涵盖改稿、证据、关联范围及修改复核字段，避免工具只声明“任意 JSON”、实际提交时却存在隐藏协议要求。
- 关系核查新增可选 `scope`：`within_document`、`across_documents`、`not_applicable`。Agent 按实际关系填写，不因上传数量强推关系。同文件正文和内嵌附件可引用同一版本；跨文件的确定结论继续需要不同文件证据；确不适用时允许说明原因。兼容旧报告未提供 scope 的情况。内置自动评审方法版本更新为 `auto-review-2`。
- 下载报告在展示时合并结构化改稿正文，Word 无法安全自动应用的修改在批注中保留具体改法；不会因 suggestion 改为短说明而丢失正文。法务已修正的建议优先。

验证覆盖短句、自定义交易角色、中文及其他语言、以此前受限词语开头的有效正文、正文与说明分开、删除、单文件内嵌附件、多文件中的单文件关系、不适用关系、同时多处错误、跨文件下标、虚构原文、越界版本和段落、人工修改保护、导出正文、Word 修订及未应用项批注。四项主要回归在修改前实际失败，修改后通过。

测试使用隔离数据库和本机模拟模型，包含真实官方 Harness SDK 子进程及 HTTP 工具流程。没有调用真实付费模型，也没有修改、继续或替换线上合同任务。提交接口仍接收完整报告，本次未引入局部报告补丁接口；减少不必要重写不等于保证整份合同的固定耗时。程序通过不代表法律结论正确，最终仍由法务复核。

验证结果：`npm test` 的 146 项单元测试全部通过。Agent、自动评审和 Word 审阅的全套相关集成测试为 54 项通过、1 项依赖浏览器的构建工作台测试跳过；随后新增普通审查用例并复测 6 项本次关键回归，全部通过，去重后共 55 项集成场景通过。新增模块语法检查及本次涉及的已跟踪文件差异格式检查通过。未启动新的线上任务，未发布代码。
