# 聊天交互与补充信息

本次改动包含聊天样式与结构化问题卡片；部署状态以对应发布回执为准。

## 使用方式

“继续沟通”采用 MUI X Chat 风格：用户消息靠右，助手消息靠左，显示头像、发送时间、复制按钮和审查等待状态。输入框支持 Enter 发送、Shift + Enter 换行，中文输入法选词时的 Enter 不发送消息。可通过回形针按钮进入现有补充材料窗口。

Agent 缺少会影响判断的身份、交易背景等信息时，自动打开沟通区，并在输入区显示问题卡片。每个问题支持单选、多选或自由文字回答，模型提供具体问题、选项和说明。用户可以切换问题核对选择，最后点击“确认并继续”；点击选项本身不会提交，也不预选任何业务事实。选项不适合时选择“其他，自行填写”，最后可追加说明。提交失败保留当前卡片中的输入，方便重试。普通问题回答默认不作为可复用法务经验学习。

旧的文字问题仍可直接输入回答；已完成的历史问答保持原记录，不根据文字自动猜测选项。

## 实现与边界

- Vue 组件为 `frontend/src/pilot/AgentChat.vue`、`AgentQuestionCard.vue`，复用原有审查会话、补充材料、停止与续审接口。只参考 [MUI X Chat](https://github.com/mui/mui-x/tree/master/packages/x-chat) 的交互和布局，没有引入 React 或 MUI 依赖。
- 问题卡片使用 [Harness user-questions](https://github.com/deepseek-ai/deepseek-harness/tree/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/interaction/user-questions) 的问题及答案字段：`questions[{id,header,question,detail,options,multiSelect}]`、`answers[{id,selected,custom}]`。通过现有法务 `request_information` 工具持久化及释放 Worker，不增加原生阻塞提问工具，不启用倒计时或自动替用户继续。
- 问题及答案存入现有 `la_agent_messages.data` JSONB 字段，无数据库迁移。问题最多6项，每项最多8个选项。卡片草稿只在当前页面保留；刷新后会重新读取待答问题，未提交选择需重新填写。
- 后端校验会话权限、当前问题版本、问题完整性、选项归属及单多选约束。提交生成可读的问答正文进入同一 Harness 会话，同时保存结构化答案；后续审查创建新结果版本。相同请求标识的重复提交返回原结果；相同标识对应不同回答返回409。
- 系统提示要求优先生成结构化必要问题。具体问题仍由模型结合合同提出；工程验证不构成法律质量评测。

## 验证

生产构建、问题/答案单元验证及 Agent 隔离数据库集成验证通过。浏览器使用生产构建和内存业务数据检查：自动显示问题、无预选、分页保留选择、显式确认、失败重试、消息复制、键盘换行、中文输入法、停止、原有材料窗口及审查标签、390px 手机布局。浏览器验证不写入正式合同或正式模型服务。

API 定义通过 `npm run openapi` 从 `scripts/openapi.js` 生成。
