# 自动评审批次与 Word 修订稿

本次完成独立的“自动评审”模块。手动上传的多份材料或新钉钉审批的一次附件收件包形成一个批次，不要求法务先分组、逐项确认意见或逐项采纳后才能生成改稿。原台账、历史审查与人工编辑流程保留。

## 已实现

- `/auto-review` 批次列表和 `/auto-review/:id` 详情，侧栏、合同详情、钉钉收件包入口。
- 多文件选择及拖拽，移除文件、上传进度、重复提交幂等、内容哈希去重、刷新恢复、移动布局。
- `auto-review-batch.js` 封装收件、解析、固定材料、计划、执行、观察、生成产物及恢复；Worker 和事务 outbox 负责执行。
- Harness 原生 `skill` 加载内置 `legal-auto-review` 及适用经验技能；预加载背景、文件清单、历史版本元数据和法律资料目录。历史版本不作为当前原文证据。
- `create_review_plan` 要求计划覆盖全部可读材料并使用已加载技能；角色附原文依据、置信度和判断理由。不按文件名或上传先后推定法律地位。
- `submit_review` 只保存候选报告；全文读取、当前版本逐字证据、跨文件补充条款/金额期限/适用顺序和改稿结构错误会回传工具，供 ReAct 纠正。`observe_review` 通过后才提交完整报告并进入改稿阶段。
- 风险意见可提供完整的 `versionId/blockId/originalText/newText/operation/reason`。仅可靠定位且给出合同正文的修改自动应用；无法判断项不自动改写。
- 每份材料独立生成不可变 DOCX，使用真实 `w:ins/w:del`。重复原文、同段冲突、复杂对象或目标段落的已有修订保留为原生批注及待核实项。
- 保留原件和源版本当前指针，不因自动改稿启动新预审或学习“法务已采纳”经验。文件报告、修改记录、失败原因、未应用意见和产物均可追溯。
- PDF 尝试复用现有且通过质量检查的转 Word 服务；DOC/ODT 使用现有 Office 转换。没有可靠 DOCX 或转换失败时保留报告并明确显示没有改稿。表格、演示材料仍可参与审查，其转换服务不产出 DOCX 时仅提供报告。
- 钉钉下载失败/不支持的附件仍列入同一批次并计入覆盖限制；附件快照变化会建立新批次，旧任务不能按新材料发布旧结论。同包重复收取不重复建批次。
- 取消会停止运行中的 Harness；恢复、重试、Worker 重启和产物生成重放均保留历史。解析失败重试会重新解析固定原件并生成新审查记录。
- 用户界面仅展示计划、工具名、业务结果摘要、技能加载和观察摘要，不展示模型内部思维链。不会向钉钉或其他对象发送文件。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /api/auto-review-limits` | 读取上传限制 |
| `POST /api/auto-review-batches` | multipart 多文件建立批次 |
| `GET /api/auto-review-batches` | 批次列表 |
| `GET /api/auto-review-batches/:id` | 角色、计划、活动、报告、历史及产物 |
| `POST /api/auto-review-batches/:id/cancel` | 停止实际运行并保留工作 |
| `POST /api/auto-review-batches/:id/resume` | 恢复，可提供更新后的背景 |
| `POST /api/auto-review-batches/:id/retry` | 重试未完成工作 |
| `GET /api/auto-review-batches/:id/artifacts/:artifactId/download` | HTML 报告或带修订 DOCX |

上传接受 `files[]` 或 `files`；`background` 为序列化 JSON；`title` 可选。`clientKey` 或 `Idempotency-Key` 提供幂等标识；同标识换材料或背景返回 409。文件数量、单文件和总大小错误返回 413。总大小在流式收件阶段即检查，避免先缓冲所有超限文件。

状态为 `queued → ingesting → planning → executing → observing → drafting → completed`，部分失败或未自动改写项进入 `partial`，未完成观察/预算暂停进入 `needs_attention`，执行异常进入 `failed`，主动停止为 `cancelled`。

## 配置与启用

| 环境变量 | 默认值 |
| --- | --- |
| `AUTO_REVIEW_MAX_FILES` | 20 |
| `AUTO_REVIEW_MAX_FILE_BYTES` | 52428800（最大 50MB） |
| `AUTO_REVIEW_MAX_TOTAL_BYTES` | 209715200（200MB） |
| `AUTO_REVIEW_DINGTALK_ENABLED` | 未设或非 `false` 时，新审批使用自动批次 |

已有审批继续使用其保存的 legacy/joint 收件模式，历史分组和审查记录不被迁移或覆盖。关闭自动钉钉模式后，新审批沿用现有联合收件开关。手动自动评审入口仍可使用。

部署需要执行 `npm run db:migrate`（新增迁移 `019_auto_review_batches.js`）、`npm run harness:build`（更新运行时插件）、`npm run build`，并重启 API 和 Worker。继续使用既有模型网关、Harness 预算和转换服务配置。此次只迁移了隔离测试数据库，没有修改现有业务数据库或替换现有部署。
