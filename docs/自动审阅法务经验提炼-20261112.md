# 自动审阅中的法务经验提炼

状态：2026-11-12 完成本地实现及隔离验收；本说明不是线上发布回执。

法务在自动评审中打开修订稿，修改正文、接受或拒绝修订、添加批注或回复后，点击“保存修改”即留下经验来源。“沉淀本次法务经验”可以选填本次修改理由和适用条件，不要求逐条填写或中断审阅。保存后可直接查看整理记录；返回自动评审批次也能查看最近二十条整理进度、失败原因及待审核草稿入口。

## 来源及边界

- 每次比较基线是法务实际打开的 `baseVersionId`，包括首次打开的 AI 自动修订稿。保存其版本 ID、文件哈希、保存后版本及本轮审查关联；文件与经验来源在同一事务中保存。首次人工保存不会把“原合同到 AI 修订稿”的差异再算成人工修改。
- 服务端从保存前后的 DOCX 提取正文、原生增删修订、批注线程及已处理状态。正文差异保留增删片段和上下文，重复段落按出现次数比较，单纯移动段落不形成新经验。
- 接受修订可能不改变当前正文，因此同时检查原生修订标记及保存后的文字。拒绝修订与接受分开记录。前端传来的操作仅作辅助，必须经文件核验；撤销后恢复的标记不计为有效决策。无法可靠定位或存在歧义时不强行判断，在来源中说明限制。
- 本次新增批注与回复作为人工输入，回复保留对应原批注作背景。原有 AI 批注及未处理 AI 修订不作为独立提炼依据。标记批注已处理、重新打开及格式变化只保存记录，不因此调用模型或生成知识。
- 主合同与其他材料都关联到所属自动评审批次的审查，不要求每个附件另有独立审查记录。访问权限、部门范围、CSRF、当前版本及并发保存检查继续有效。
- 下载文件和打开审阅本身不触发提炼；仅本地修改且未回传的文件不会进入系统。

## 提炼及复用

实质处理进入现有 `agent-memory` 后台队列。模型依据人工修改、经核验的处理、批注回复及明确理由，尝试提炼可执行的检查步骤、适用条件、例外和改法，区分审查技能与案例经验。没有足够依据允许返回空结果。

拒绝一处修订只说明该处文字未采用，不证明原条款正确；未填写理由时保留“修改原因待确认”。个案金额、日期、账期和比例不能成为公司统一标准。合同、批注和反馈中的指令均作为待分析数据。

每条候选至少逐字引用一条本次人工贡献或核验决策的证据。只引用原有 AI 内容或背景会被拒绝。来源保存候选与引用的对应关系，来源详情显示初次提炼依据、正文变化、修订处理、批注回复、可选理由及无法确定事项；原有脱敏校验继续执行。

候选进入现有草稿审核流程，审核前不参与其他审查。审核通过且启用后，仅供同部门后续审查按适用条件复用；可按已有功能设为系统技能。失败保留来源并可重试；撤销来源会停止派生知识复用。重复保存与完成任务重放不重复生成。

## 实现及验收

`review-learning.js` 负责服务端文件证据比较；`word-review.js` 在保存事务中记录 `review_revision` 来源，避免同时触发旧的正文差异来源。来源使用已有 JSONB 和队列，不需要数据库迁移，不重写历史合同或历史知识。

验证使用虚构合同、隔离 PostgreSQL、真实 Edge 与实际 DOCX 导出，不修改正式合同或调用真实模型。模型提炼采用确定性适配器验证证据校验、草稿生成、审核和后续可用知识；不据此宣称法律质量或真实模型泛化效果达标。

- `npm test`：152 项单元测试通过，包含 AI 内容隔离、仅状态处理、接受/拒绝、撤销、重复修订、批注线程、段落移动与逐字证据校验。
- `node scripts/test-agent.mjs backend/test/integration/auto-review.test.js backend/test/integration/word-review.test.js backend/test/integration/memory-management.test.js`：40 项通过、3 项可选浏览器测试跳过；验证附件来源、基线、幂等、草稿、审核及复用。
- `node scripts/test-agent.mjs scripts/qa/auto-review.cjs`：8 项真实浏览器测试通过，包含接受与撤销修订、批注回复、修改理由、保存、查看来源及批次进度；未处理 AI 内容和状态变化不生成知识。
- `npm run build` 与 OpenAPI 生成通过。浏览器验收证据位于 `.local/auto-review-qa/`。

发布时需同时更新服务端、Worker 和前端，避免继续运行旧版提炼逻辑；沿用现有备份、部署锁、候选验证和原子切换流程。历史来源不自动回填或发布；仍在旧页面中的浏览器应刷新后使用新增的理由和操作记录。
