# 钉钉多附件分组与联合审查

## 使用方式

新流程启用后，首次收取的新审批在「合同与待办」显示为待确认审批分组。打开后统一查看全部附件的文件名、格式、收取状态、解析状态和错误；支持重新收取、重新分析、补传同一附件及添加关联材料。

AI 提出分组建议，法务确认。每组恰好一份主合同，其他文件明确选择为补充协议、价格及履约附件或参考材料。参考材料可以明确选入多组；同一文件不能成为多组主合同。同名文件以独立附件标识区分。所有文件必须归组或填写排除原因，选入的文件无法读取时禁止确认完整分组。

确认后台账按合同组展示。各组先独立进行异步预分析，沿用主体、立场、模板、审查点和目的的确认流程，然后开始联合审查。可以离开页面，任务进度和结果保存在数据库；一组失败不会阻塞其他组。合同详情保留返回审批附件总览的入口。

## 三类固定对照

- 补充条款对照：对应主合同和补充协议的准确原文，说明替换、新增、删除及其影响。无法对应时待确认，不把两份独立文件作为新旧稿比较。
- 金额与期限：核对币种、含税口径、计价范围、付款、履约期限、续约和终止；呈现双方文件版本、段落及逐字引用。
- 文件适用顺序：仅依据明确的变更、优先适用、生效条款，不按文件名、上传先后或日期推定效力。缺乏依据或约定矛盾时待确认。

每份材料完整分片读取。主合同和补充协议参加条款检查；所有材料提取相关要素后，对每一对文件进行独立交叉核对。覆盖记录保存每份文件、要素分片、各文件对和检查批次。单文件组明确说明跨文件对照不适用，不声称已审查未提供材料。原文识别或转换需要人工核实时，仍生成待处理核实项。

## 多文件修订与经验

联审页可切换本次快照中的文件，引用可返回来源文件。支持的 Word 沿用 OnlyOffice 修订。切换前保存，保存失败或保存过程中又发生修改时保留现场。同一份补充协议生成自己的新版本；本机下载、修改再上传也保存到当前所选文件。

成员改版会清除引用组的当前审查指针并重新预分析；共享材料改版影响所有引用它的组。新增材料先确认归属。旧审查、处理意见和结论不覆盖；报告和 Word 批注始终按本次冻结版本定位。最终结论绑定整组文件版本、角色、哈希及明确排除记录。

结论确认后沿用自动经验整理开关。经验输入包含整组来源及人工处理；每份文件仅与自己的直接上一版对比，同时输入跨文件处理依据。提案允许编辑、采纳为草稿，正式发布后才用于后续审查。测试只使用隔离数据库与虚构材料。

## 接口与数据

迁移 `012_joint_intakes.js` 新增审批模式、收件包、附件、合同组及关系表，复用合同原件和版本存储；增加意见的目标文件建议、结论的材料快照字段。不复制正文，不删除旧记录。

`/api/dingtalk/intakes` 提供列表和详情；`/:id/groups` 保存草稿，`/:id/confirm` 确认分组，`/:id/analyze` 和 `/:id/retry` 异步解析和收取，`/:id/documents` 添加材料，`/:id/documents/:documentId/file` 补传/修改。

写操作沿用登录权限、角色、CSRF、Origin 和 revision 校验。整包事务锁先于合同锁；分析任务使用 token 和会话锁，重启时仅恢复已失去工作进程的任务。新流程文件不能绕过分组直接单文件审查。分配法务可访问所负责审批包的材料，不能越过审批包和接收账号边界。

## 启用与历史边界

开关为 `la_settings.dingtalk_joint_intakes`，默认关闭；管理员在「钉钉收件」启用。首次接收时固定审批的处理模式，按应用、审批实例和接收账号隔离。既有收件、开关关闭期间首次接收的审批、以及启用时间之前已接收的审批保持旧流程，后续更新不改模式。

不重分组历史记录、不重跑历史审查、不覆盖已保存结论、不发送钉钉消息、不回传附件。文件大小沿用 50 MB 限制。AI 分组失败可以人工分组，失败原因保留；缺失/无法读取的选中材料会阻止完整审查。

发布前在隔离库完成迁移、回归和虚构样本验收；正式数据备份后迁移、切换并启用开关。发布后检查旧记录数量、经验开关、队列、转换服务和 OnlyOffice 健康。完整验证记录和发布回执保存在本轮发布目录。
