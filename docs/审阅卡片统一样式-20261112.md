# 审阅卡片统一样式

2026-11-12。用户要求自动评审改稿中的卡片全部采用已有合同审阅批注卡片的样式。

自动评审的 `AutoReviewDocument.vue` 与普通合同入口 `AgentReview.vue` 原本均引用 `WordReviewWorkspace.vue`，页边卡片均由 `ReviewMarginRail.vue` 渲染。截图差异来自同一组件对原生 Word 批注和正文修订使用了两套卡片样式：修订卡片为紫色且只有勾叉，批注卡片为橙色且显示头像、时间和文字操作。

本次统一使用已有批注卡片的橙色头像、作者、原始时间、背景、边框、虚线连接和底部文字操作。保留“替换正文 / 删除正文”等内容标签，用删除线与插入文字说明具体变化；正文中的紫色原生修订痕迹继续显示。两个入口继续共用同一工作区和卡片组件。

修订操作移至底部，明确显示“接受修订 / 拒绝修订”，移除顶部勾叉。操作成功显示结果说明及“撤销此次操作”；发生后续文档修改后不再提供这个专属撤销入口，防止误撤销后续编辑。操作失败只显示错误，保留待处理修订。批注继续提供回复、标记已处理和重新打开。

“接受修订”将修改合入当前正文并移除对应待处理修订；“拒绝修订”恢复该处修改前正文并移除该修订。“标记批注已处理”只改变批注状态、保留卡片和回复。统一样式没有把这两种文档操作混为一种。没有新增持久化的修订决策卡片或独立数据库记录；原合同和历史版本仍保留，当前修改需保存。

验证采用本机虚构 DOCX、隔离数据库和真实浏览器，不修改生产合同、不调用真实模型：

- `node scripts/qa/review-card-style.cjs`：5 组检查通过。修改前实际失败于修订卡没有头像；修改后确认两类卡片样式一致、顶部无勾叉、时间可见、底部文字操作、接受与拒绝的结果及撤销、OOXML 正文实际变化、批注处理不改正文、操作失败不误报成功、后续编辑使专属撤销入口失效。
- `node scripts/qa/margin-review.cjs`：11 项既有工作区检查通过，包含导出、原生批注及修订、处理状态保存重载、滚动缩放定位、回复、编辑、撤销和保存失败保留数据。
