## 已在组件测试中复现并修复

| 问题 | 修复行为 |
|---|---|
| 复制已发布技能后没有“添加方法”按钮 | 复制模式复用新建、草稿模式的添加入口；可添加、删除并保存新版本；删除全部方法后禁用保存 |
| 技能修改后刷新、关闭页面缺少保护 | 注册 `beforeunload`；保留原有关闭与路由离开确认，取消时保留输入；组件销毁时移除监听 |
| 保存技能期间仍可关闭、改变输入或切换编辑对象 | 保存期间禁用表单控件，阻止关闭和切换；请求失败保留原内容，成功采用服务器返回的版本和 revision |
| 旧技能来源请求晚返回，覆盖当前版本的来源 | 请求编号固定当前编辑对象；切换、关闭或销毁后，旧响应和旧错误不再写入 |
| 经验提案直接关闭、刷新或跳转会丢失修改 | 加入编辑基线、关闭确认、刷新及路由离开／更新保护；取消时保留内容 |
| 提案保存期间可关闭并丢失现场 | 保存期间禁用输入与关闭；失败保留提案，成功关闭并刷新；已允许的合同切换清除旧合同编辑状态 |
| 任务列表旧请求覆盖新结果，恢复后残留读取错误 | 仅采用最近一次加载结果与错误；成功清除错误，销毁后忽略响应并停止轮询 |

## 浏览器可用后的接手步骤

1. 使用当前 Codex 浏览器运行时连接并读取可用浏览器列表。连接成功才继续页面操作；若仍返回 Work 禁用，向用户报告真实原因，保留本地修复。
2. 启动既有本地 PostgreSQL，再运行 `.local/skills-edit-qa/manual-server.cjs`。该临时辅助脚本创建 `legal_manual_skills_` 前缀的独立数据库、虚构合同、已发布采购技能及待确认提案，在 `http://127.0.0.1:18130` 提供当前构建；不启动 Worker，不调用外部模型。登录信息写入同目录 `access.json`，保持在忽略目录。该脚本属于本机辅助文件，不随 Git 或正式发布交付。
3. 从登录页填写隔离账号；按可见页面的元素逐步操作，并保存修复后截图。重点检查以下路径：
   - 分类与规则中心 → 已发布技能 → 创建新草稿 → 添加方法 → 删除方法 → 保存 → 重新打开核对；检查只读历史、提交、发布及 Markdown 下载。
   - 技能／提案修改后，分别按 Escape、关闭、页面跳转和刷新；取消丢弃后内容保留，确认丢弃后正常关闭；保存后离开不重复提示。
   - 通过测试环境制造保存延迟及失败，确认保存期间不能改动或关闭、失败保留输入，重试成功后内容一致。
   - 反馈中心 → 编辑提案 → 保存 → 采纳 → 技能草稿 → 编辑发布，确认范围与条件语境保留。
   - 快速切换版本／合同、连续刷新、窄屏和浏览器控制台；旧来源与旧任务不覆盖新选择，页面无运行错误。
4. 浏览器验收通过后，从线上当前发布建立新基线与新 tag，只覆盖本轮确认的文件。完成备份、源码哈希校验、候选构建及相关测试后原子切换，保持当前自动整理开关和全部经验数据；本轮无迁移。不要重跑 `.local/skills/` 的旧发布脚本覆盖历史回执。
5. 更新本文、[主交接文件](AGENT交接-录音反馈修复与上线.md)及发布证据，分别记录实际浏览器、测试替身、真实模型和真实编辑保存的覆盖范围。完成标准为浏览器验收、发布及线上复测均有证据，不能把本地测试写成已上线。

测试结束后向临时服务 stdin 写入 `stop`，或发送 SIGINT，服务会关闭并删除本次独立数据库。停止本轮启动的 PostgreSQL 前先确认没有其他本地任务在使用。
