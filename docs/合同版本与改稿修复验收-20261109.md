### 真实编辑器验收额外发现并修复的问题

OnlyOffice 在最新键盘输入尚未同步到其服务端时，可能对 force-save 返回 `error=4`。原实现将这视为无改动，清除了待保存状态。本轮真实编辑器验收先复现失败，再增加确定性回归；修复后继续重试并等待后端签名 callback 确认新版本，超时则保留编辑内容。

证据日志：`.local/bug-audit/force-save-flush-red.log`、`force-save-flush-green.log`；回归记录为 `force-save-flush-retry`，先收到无改动响应，第二次请求后确认 v2。

## API 与数据兼容

- `GET /api/contracts/:id/editor` 新增可选 `versionId`，新前端必传。请求版本不是当前版本时返回 `409 EDITOR_VERSION_CHANGED`；不传参数的旧客户端仍可打开当前版本。
- `POST /api/reviews/:id/annotated-version` 请求格式不变。首次生成使用历史源版本时返回 `409 ANNOTATION_REVIEW_STALE`。检查位于共享服务，前端与 Harness 工具调用都受保护。
- 同一报告、模式和意见摘要的并发生成只创建一个版本；精确重试返回原产物，不移动当前版本；改变模式或意见后不能绕过历史版本校验。
- 历史批注下载仍可用。无需数据库迁移；没有删除或重绑已有文件、报告、批注和结论，也未自动处理可能存在的历史异常版本。
