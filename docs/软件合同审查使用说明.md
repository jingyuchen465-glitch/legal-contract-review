# 软件合同审查

适用类型为「软件许可合同」，包括定制软件开发、既有软件许可、SaaS 订阅和配套维护。分类依据主要交易实质，检查项会要求模型根据实际交易判断适用性，不能把未购买的开发或源码服务机械视为缺失。

## 直接试用

1. 在「接入与模型配置」完成真实模型配置与连接验证。
2. 上传 PDF 或 DOCX，填写我方主体、交易立场和目的；进入合同详情。
3. 点击右上方「示例规则试审」，或待处理提示中的「使用示例规则试审」。
4. 等待解析、分类、规则匹配、预审与引用校验。左侧查看检查项，中间定位原文，右侧查看解释与建议。
5. 可以保存人工复核意见，下载 HTML、DOCX 或 PDF 报告。页面及报告均注明示例模式。

没有已发布规则时，默认正式上传任务会提示待处理。这时可显式选择示例试审；系统不会悄悄把待审核草稿当作正式标准。模型未配置、引用无法验证、规则检查不全或输出不合格时，仍会停在待处理状态。

预审每批最多检查 5 项规则，每批读取对应合同片段的完整内容，返回后更新任务进度。15 项检查分为 3 批；长合同再按结构分片，所有批次与片段通过校验后才显示完成。任一批次漏检或引用无效，不能把部分结果当作完整报告。模型供应商速度、限流和网络均会影响耗时，页面进度不代表法务已批准。

普通模型调用默认等待 120 秒；条款审查批次默认最多等待 300 秒，可通过 `MODEL_REVIEW_TIMEOUT_MS` 调整，且不会缩短已有的更长 `MODEL_TIMEOUT_MS` 配置。超时和暂时性错误仍最多尝试三次，429 按供应商指定等待时间重试。

## 检查内容

通用 4 项为交易主体、付款、责任限制和争议解决，另有软件专项 11 项：

| 检查项 | 重点 |
|---|---|
| 服务范围与需求变更 | 功能、容量、接口、部署、交付清单及变更流程 |
| 交付进度与验收标准 | 里程碑、测试指标、异议期限、默认验收、缺陷复验 |
| 付款与维护费用 | 高额预付、验收前付清、单方调价及隐藏费用 |
| 许可范围与限制 | 期限、账号、地域、部署、关联公司、续费与停服 |
| 成果与知识产权 | 既有技术、定制成果、源码、维护权限及侵权救济 |
| 维护与连续性 | 维护起算、响应及修复、备份恢复、兼容和免责 |
| 数据处理 | 合同训练用途、处理范围、存储期限、事件通知及删除 |
| 分包及第三方 | OCR、模型和云服务接收方、告知授权及供应商责任 |
| 解除与迁移交接 | 退出费用、预付款、导出、接口、交接及备份清理 |
| 违约与赔偿上限 | 双方责任失衡、数据及知识产权是否受过低上限限制 |
| 通知及争议冲突 | 邮件送达、地址变更及诉讼与仲裁关系 |

指令同时包含正常边界，例如不将商业软件未交源码、高额预付款或使用第三方服务直接判为违法。已有条款结论必须提供可验证的原文引用；缺失项不伪造原文；没有检索到法律资料时不编造法条。判断质量仍须由法务用历史样本评测。

## 转为正式使用

在「分类与规则中心」可查看软件参考规则草稿；旧库运行 `npm run seed:demo` 可补齐，现有版本不被覆盖。

发布人在「分类与规则中心」点击软件规则包的「编辑草稿」，通过中文表单核实规则及可追溯资料，适用方式选择「按合同类型」，勾选「软件许可合同」。保存后提交审核并发布。无须填写 JSON 或英文类型编号；通用规则需另行审核发布，正式模式不会自动拼入未发布示例。详见[规则配置使用说明](规则配置使用说明.md)。

回到合同详情，点击「正式重新预审」。正式任务完整完成、分类及立场确认、待处理风险均完成后，法务才可提交最终结论。示例试审即使完成全部复核，服务端也不接受最终结论；必须重新执行正式任务。

## 模式与历史记录

- `snapshot.reviewMode=trial` 为示例试审，`formal` 为正式预审；旧记录无此字段时按正式模式解释。
- 示例规则在任务建立时固定到快照；后续代码升级、草稿修改或正式发布不会改变这次试审。
- 试审使用固定内置规则，与用户编辑中的草稿分开。草稿改动需确认发布后，通过正式重新预审使用。
- 试审期间上传修改稿、纠正分类或补充背景，新预审继续使用示例模式；显式点击正式重新预审才切换模式。
- 新预审不创建重复文件版本，不覆盖旧预审、人工意见或结论。
- 目录状态来自已发布专项规则；其他目录类型也可通过发布对应类型的规则启用，无须再改后端类型白名单。

## 验证边界

新增集成测试覆盖软件示例安装幂等、规则不自动发布、15 项检查及引用校验、示例报告标记、阻止试审最终结论、正式发布后完整结论流程、其他类型动态启停和版本模式保留。测试模型使用明确的工程夹具，不能当作法律识别准确率。

软件类新增范围尚未经过公司法务的历史样本质量验收。真实模型对单份模拟合同跑通，只证明该配置与流程可运行，不证明所有软件合同已经达到原有两类试点的质量目标。
