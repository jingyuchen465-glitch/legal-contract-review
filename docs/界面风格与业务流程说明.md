# 界面风格与业务流程

本轮按用户最新要求执行：**结构沿用现有线上，风格参考上游，功能保留本项目。** 不采用将整套应用切换到上游首页、知识库和独立审查页面的方案。

## 页面与功能

- 保留侧栏、顶部路径、合同台账及四项统计卡片。
- 保留原上传窗口中的多格式文件、合同类型和业务背景；类型与背景可选填，最终确认放到预分析后的确认页。
- 保留审查详情的清单、原文批注、版本切换、在线编辑、法务复核、最终结论、下载与归档。
- 保留补查待确认、钉钉收件、反馈评测、经验沉淀、模型配置和运行审计。
- 规则中心退出日常导航，合同经验技能仍可直接访问；已有高级标准及分类指导功能保留供反馈入口使用。

`frontend/src/pilot/appearance.css` 仅覆盖配色、字体、边框、卡片和按钮；侧栏宽度、内容分区、表单及业务操作沿用现有工作台。默认路由继续使用 `frontend/src/pilot/` 与 `backend/pilot/`，不挂载上游独立业务接口。

## 点击合同后的确认流程

工作台上传与钉钉新收件先执行后台预分析，台账显示排队、预分析中、待确认或失败。进度不通过覆盖全站的阻塞弹窗展示，离开页面不取消任务。进入详情后按参考截图展示三步进度、AI 识别的具体合同名称、合同预览、主体立场、模板、多选审查点和可编辑核心目的。

主体下拉框展示从原文识别并验证过名称引用的完整签约方和交易角色；遗漏可人工补充。本项目十四类业务模板与上游 `backend/data/reviewTemplates.json` 的二十五个模板均可选择，并叠加 AI 从本合同识别的特有审查点。模板只是检查候选内容，用户最终勾选的内容才会执行。

法务点击「开始分析」才创建正式审查任务。提交事务校验合同及预分析版本、权限、所选主体、模板和检查项；重复开始返回同一个正式任务。正式任务固定主体、立场、目的、检查指令和依据，仍使用已有证据核验、分批审查、恢复重试、人工复核及最终结论机制。上传新正文版本会产生新的预分析，旧报告保留且不能用于批准新版本。

草稿选择自动保存在服务器，当前浏览器暂存尚不完整的编辑。原有 API 客户端省略 `reviewFlow` 时兼容旧自动审查协议；当前工作台始终显式提交 `guided`，历史报告不做批量重写。

## 不再要求维护规则包

`review-defaults.js` 提供全部十四类合同的内置审查要点，由原有审查流程自动加载。已有公司专项标准仍优先适用；只有通用公司标准时，叠加对应类型的内置专项检查。草稿、审核中及已停用版本不会自行生效。

内置检查项不写入公司发布表。每次新任务在创建时固定全部候选检查项，分类后匹配适用范围，沿用原有分批检查、证据核验、断点重试和人工结论要求。既有任务的快照、意见、原件及结论保留。旧的缺规则待处理记录需要创建新预审，避免混用历史标准。

## 验证

- 单元测试覆盖全部十四类内置审查、快照独立、公司标准优先及草稿隔离。
- 集成测试覆盖零发布包预审、软件合同完整检查、转换文件、原有复核审批、版本、反馈、经验、钉钉、权限及备份。
- `scripts/workspace-style-qa.cjs` 使用独立 PostgreSQL 与真实 Edge 浏览器，验证原侧栏台账、审查布局、多格式上传表单、真实业务接口、人工复核、各模块和窄屏页面；审查响应使用明确的本地测试数据，不代表真实模型质量验收。
- `backend/test/integration/preanalysis.test.js` 覆盖持久队列并发、HTTP 响应、确认前无正式任务、选择保存、版本失效、权限、幂等和确认范围真正传入审查模型。
- `scripts/preanalysis-ui-qa.cjs` 通过真实 Edge、真实接口与 worker 验证离开恢复、主体/模板选择、检查多选、目的编辑、刷新恢复、正式审查及 980/390 像素显示；AI 响应为明确的工程测试数据。

本轮本机改动尚未发布到正式站点。
