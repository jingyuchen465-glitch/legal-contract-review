# 部署与操作手册

## A. 当前电脑的开发运行

Node.js 24、npm 和 Git 已就绪；Docker / WSL2 未就绪。原生开发验证不依赖安装 Windows 数据库服务。

```powershell
npm ci
# 终端 1：启动开发 PostgreSQL，首次生成本机随机配置，不覆盖已有 .env
npm run db:local
# 终端 2
npm run db:migrate
npm run setup:local
npm run dev
```

访问 <http://localhost:8080>。初始账号见 `.local/initial-admin.txt`；文件含随机密码，不提交 Git。全部账号统一为系统管理员，在“管理员账号”建立各位法务的独立账号，无需分配角色。

当前会话已启动原生 PostgreSQL、API、Worker 和 Vite。进程关闭后按以上步骤重新启动。数据库位于 `%LOCALAPPDATA%/LegalAgentDev/<项目路径哈希>`；应用文件位于 `.local/data`。这是开发模式的可写替代路径，正式试点通过 DATA_ROOT 配置到 D 盘。

原生 PostgreSQL 包不附带备份客户端，可通过官方 EDB 发行包准备：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/postgres-tools.ps1
npm run backup
```

该脚本只提取 pg_dump / pg_restore，不安装系统服务。官方发行包缓存在忽略目录，运行路径写入 PG_DUMP_PATH / PG_RESTORE_PATH。正式运维应安装并维护匹配主版本的 PostgreSQL 客户端。

## B. Windows 容器试点

先由电脑管理员完成 WSL2、虚拟化和 Docker Desktop / 公司认可的容器运行环境；该步骤可能需要系统安装、重启或许可确认，本次未执行。

1. 复制 `.env.example` 到 `.env`，设置 DATA_ROOT 为 `D:/LegalAgentData`。
2. 为 POSTGRES_PASSWORD、SESSION_SECRET、TOKEN_SECRET、OCR_TOKEN、ONLYOFFICE_JWT_SECRET、MINIO_ACCESS_KEY、MINIO_SECRET_KEY 分别生成独立随机值。数据库密码使用 URL 安全字符，建议十六进制。
3. 本机 PUBLIC_URL 为 `http://localhost:8080`，OnlyOffice 浏览器地址为 `http://localhost:8081`。Compose 内部地址由编排提供。
4. 执行 `docker compose config --quiet`，之后 `docker compose up -d --build`。未在本机验证这些镜像和容器。
5. 用 `docker compose run --rm -e BOOTSTRAP_PASSWORD api backend/pilot/cli.js bootstrap` 创建初始管理员；先在终端环境设置密码，避免把密码写入命令历史。
6. 检查 `docker compose ps`、`docker compose logs --tail 100 api worker ocr`；不得粘贴含配置密钥的完整环境输出。

Compose 只把 8080、8081 绑定到 127.0.0.1，数据库和检索服务不暴露主机端口。正式内网多人访问需反向代理、HTTPS、认证入口和批准的访问范围。NODE_ENV=production 要求 PUBLIC_URL 为 HTTPS；反向代理需正确传递协议，参照后端 proxy 配置说明。

容器数据分开保存在 `D:/LegalAgentData/postgres` 和 `D:/LegalAgentData/application`，对象、分类目录、派生文件和备份在 application 内。Milvus 可从已发布资料与缓存重建，原始合同以数据库和 objects 为准。

## C. 第一次试用

1. 为各位法务建立独立管理员账号；部门仅作备注，管理员可查看全部合同。
2. 在“接入与模型配置”填写指定模型服务地址（含 /v1）、名称与密钥。没有模型配置时上传任务进入待处理。
3. 发布人在“分类与规则中心”查看通用、采购、海外仓及软件四个示例草稿，以及其他合同类型的专项规则草稿，以公司标准核实后提交审核并发布。旧库运行 `npm run seed:demo` 可补齐全部目录类型的规则草稿，已有版本不会被覆盖。示例不直接当作法务认可标准；也可在详情页点击「示例规则试审」体验模型及复核流程，但不能据此确认最终结论。
4. 业务提交 PDF / DOCX，并填写我方主体、交易立场、交易目的。扫描件先准备 OCR，DOC 先转为 DOCX。
5. 法务确认分类与立场，在三栏详情逐项核对，采纳、驳回、修正或标记补件。必要时退回修改。
6. Word 修改稿或 OnlyOffice 有效保存产生新版本；旧复核保留，新版本重新审查。补充材料和签署件在上传类型中单独选择。
7. 所有风险和不确定项处理后提交最终结论；附条件同意填写条件，不同意填写理由。
8. 下载当前终稿与报告，人工回传钉钉，再记录回传并归档。签署件独立上传关联。

## D. 服务配置

- 模型：OpenAI 兼容 `/chat/completions`；要求 JSON 输出。可在管理员页面更新，密钥加密保存，页面只显示是否配置。
- Embedding：设置 EMBEDDING_MODEL，使用相同指定网关 `/embeddings`；配置 MILVUS_ADDRESS。已有资料过长且无检索服务时会停止，不能静默省略。
- OCR：`ocr/app.py`，FastAPI + PaddleOCR CPU，OCR_TOKEN 至少 32 位，首次需下载模型。企业离线环境应提前放入经确认的模型文件。
- OnlyOffice：启用 JWT，配置浏览器地址、内部地址及回调可访问的后端地址。仅 DOCX 编辑，PDF 预览。服务要能访问签名文件 URL。
- Jev：JEV_API_KEY / JEV_MODEL / JEV_BASE_URL 环境变量，首期只运行离线评测。不会自动切换正式分类器。
- 钉钉：管理员在“钉钉接入”保存企业内部应用凭据并启用，接收人在“钉钉收件”绑定本人的钉钉账号。审批分配给绑定账号时自动下载审批表内的 PDF、DOCX，无需模板、节点或字段映射。应用需授权审批读取、附件下载、企业账号映射及个人信息读取，配置 OAuth 回调与 Stream 的 bpms_task_change 事件。详见《钉钉自动收件配置》。

钉钉下载接口为 `/v1.0/workflow/processInstances/spaces/files/urls/download`，事件处理和已知审批复查均只读审批，不执行同意或拒绝。真实附件格式、当前办理人状态及下载域名必须通过企业联调验收。

## E. 故障与并发

“运行与审计”显示任务状态、错误码、接入待确认和备份信息。修复配置后可重试原任务；模型配置改变且原任务已有快照时，应由授权用户创建新预审。

单次模型 HTTP 请求最多三次，429 等待服务端 Retry-After。配置和权限错误不重复尝试。进程崩溃后队列按心跳恢复；人工复核与结论不会随重试被覆盖。扫描件 OCR 并发 1，初始审查任务并发 2。

预审任务创建时会固定模型服务、模型名称和配置签名。预审执行期间如果模型地址、名称或密钥发生变化，旧任务会暂停并提示重新创建预审，不能通过“重试原任务”混用新配置。历史未完成且没有模型快照的任务也需要重新创建；已经完成的历史报告不受影响。

合同被法务退回后，原预审只读保留证据、报告和反馈入口，不能继续修改风险或确认结论。请上传修改版本或创建新的预审任务后继续处理；补充材料和签署件不会解除原预审冻结。

PDF 解析会跳过确认的空白页；含图像或无法提取正文的非空页才会调用 OCR。没有 OCR 配置时，真实扫描页会进入待人工处理，文字页和空白尾页不应因此失败。

电脑需保持开机；服务退出后先重启数据库，再启动应用与 Worker。不要清空数据目录来“修复”迁移；先备份、检查错误和迁移版本。

## F. 备份与恢复

Worker 每日尝试备份，成功后保存 `manifest.json`。保留默认 30 天成功备份；没有成功清单的失败目录不会冒充有效备份，也不会自动当作成功备份删除。

```powershell
npm run backup
# 恢复必须使用提前建立的独立空数据库与独立空目录
$env:BACKUP_DIRECTORY='D:/LegalAgentData/application/backups/backup-...'
$env:RESTORE_DATABASE_URL='postgres://用户:密码@地址:端口/新的空数据库'
$env:RESTORE_DATA_ROOT='D:/LegalAgentRestoreDrill'
npm run restore
```

恢复校验全部清单哈希、文件版本与数据库关系，清理恢复出的会话。恢复失败后不要把不完整目标切换为正式实例。

保管原 TOKEN_SECRET 才能解密数据库中的模型密钥；.env 应单独安全保存，不放入普通合同目录。迁移服务器先备份、恢复到独立目标、校验文件数量和哈希、试跑虚构合同，再变更域名与集成配置。不要在目标验证完成前删除源数据。

## G. 验证命令与上线前事项

规则配置现在通过「分类与规则中心」的中文表单完成，操作见[规则配置使用说明](规则配置使用说明.md)。修改旧版另存草稿，提交审核并发布后才用于后续预审。

```powershell
npm test
npm run test:integration
npm run build
npm audit --omit=dev
```

集成测试需要运行 PostgreSQL、具备创建测试数据库权限及 pg_dump / pg_restore。测试只使用随机命名的 `legal_test_*` / `legal_restore_*` 独立数据库，不清空现有合同。

上线前仍需：容器与 OnlyOffice 联调、CPU OCR 实测、Milvus 实例联调、指定模型真实接口、钉钉真实审批、两类各不少于 20 份法务标注样本、独立质量验收、公司镜像扫描与许可核实。不要把配置标志显示为“已联通”或把测试数据视为正式法律标准。
