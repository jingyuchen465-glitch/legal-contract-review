# 系统技能与长期知识

项目的知识分为系统技能、审查技能和案例经验。在“法务经验 → 可复用知识”中可按分类查看。

| 分类 | 来源与保存方式 | 审查中的使用方式 |
| --- | --- | --- |
| 系统技能 | 随项目维护，页面只读 | 在适用审查中必须加载；不走部门知识的草稿审核与启停流程 |
| 审查技能 | 数据库中的长期知识，可人工录入或从法务处理提炼 | 已审核、生效且部门匹配的方法进入固定目录，Agent 按适用条件读取 |
| 案例经验 | 数据库中的长期知识，保留来源及适用条件 | 已审核、生效且部门匹配的经验供检索，个案结论不自动成为公司标准 |

会话笔记由 `update_task_notes` 保存，只衔接当前审查，不属于跨合同长期记忆。旧规则、旧技能和历史知识库不因本次接入重新启用。

## 已接入的系统技能

- `legal-practical-redline`：法务实务审改，适用于每轮新建审查、继续审查和修改复核。正文位于 `skills/legal-practical-redline/SKILL.md`，必读范例位于同目录的 `references/examples.md`。
- `legal-auto-review`：多文件自动合同评审，适用于自动评审批次，负责角色识别、计划、跨文件核查和结果观察。

实务审改技能要求直接修改有实质问题的正文，未知商务条件留具体短提醒，重大问题保留必要原因。它约束审改方法；宿主的结构化审查字段及 Word 导出实现仍独立存在。本次接入未改写 Word 批注的拼接格式。

## 必读如何保证

1. 建立每轮审查时读取项目技能目录，将正文、必读范例和内容哈希一起写入审查快照。文件缺失时明确报错，不静默跳过。
2. 执行审查前主动预加载正文和范例，记录 `skill_loaded`（`mode=required_preload`）及 `skill_resource_read`。Agent 不需要自己猜测何时加载。
3. 模型桥接在每次请求中强制带入该轮快照中的正文和范例；恢复、追问或上下文压缩后仍带入。`system_skills_injected` 记录该次请求携带的技能版本。
4. 读取审查正文、制定自动评审计划、提交报告和最终保存时校验本轮的必读记录。仅加载技能名称或另一轮、另一版本的记录不能通过。

上述记录证明内容已装载并随模型请求提供，不能证明模型法律判断正确或已经遵循每一项方法。具体改稿质量仍需用合同结果验证。

## 更新与历史

修改项目内的技能正文或范例后，新建的下一轮会使用新内容版本；已有审查继续使用其固定快照，历史结果不回写。继续会话时如系统技能版本变化，清除旧运行时上下文，避免沿用过期方法。接入前已建立的审查保留原输入；需应用新技能时创建新一轮或继续审查。

Docker 镜像已包含 `skills` 目录。前端“系统技能”分类及只读接口 `GET /api/agent/system-skills` 用于查看当前项目版本；具体某轮使用什么，以审查快照和加载记录为准。
