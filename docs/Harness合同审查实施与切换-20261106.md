# Harness 合同审查实施与切换

## 本次实现

新审查是持久 Agent 会话：上传合同 → 自主阅读材料、检索和使用技能 → 带证据的意见 → 继续沟通、改稿或整体确认结论。前端继续使用 Vue，ReAct 指模型判断、调用工具、观察结果的循环。

已移除新任务中的独立预分析、模板和审查点选择、正文×规则×技能固定分批执行及旧经验提案采纳/审核发布入口。旧审查执行器不再运行，旧写接口返回 `410 REVIEW_ENGINE_RETIRED`。旧规则、技能和经验不进入新快照。旧数据不删除，保留查询与导出；历史设计文档只反映当时实现。

原件、转换/OCR、钉钉收件、附件关联、PDF 转 Word 和 OnlyOffice 继续使用现有基础能力。联合收件的材料归属确认用于区分同一审批中的交易，不是选择审查点。确认后各组在自己的同一 Agent 会话中读取关联文件。

## 固定源码与构建

- 官方仓库：<https://github.com/deepseek-ai/deepseek-harness>
- 提交：`fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`
- 官方包：`0.2.2-rc.1`；Node ≥24.9；pnpm `11.28.5`。
- 官方源码归档 SHA-256：`44926eb97c791d1b7a640a0146aa1c522aae7c21a8e238576820d01445cff976`。

在仓库根目录执行：

```powershell
npm ci
npm run harness:build
npm run build
```

构建器 `scripts/build-legal-harness.mjs` 验证归档哈希，使用上游锁文件安装同版本 SDK、内核及插件，编译 SDK，并通过官方源码 CLI fallback 运行 `sdk-minimal`。不构建上游桌面/网页发行产物。默认目录 `.local/legal-harness`，可用 `LEGAL_HARNESS_ROOT` 指向独立目录；不要把不同平台的 node_modules 互相复制。

生成 `legal-runtime.json`、上游 `LICENSE` 与 `dependency-licenses.json`，随运行时交付。首次依赖安装可能较久且占用较大空间。Dockerfile 独立构建运行时并放置于 `/opt/legal-harness`，本机尚未做实际容器构建和启动验收。

Linux/macOS 构建还调用官方 `native/system/scripts/build.ts --host-addon-only`，编译会话持久化使用的 POSIX 文件锁模块。构建机需要 `cc` 和当前 Node 安装的开发头文件；Docker 的 Harness 构建阶段已安装 `build-essential`。只构建当前宿主的 Node-API 模块，无需构建已禁用的 shell 沙箱发行物。

法务插件位于 `runtime/legal-harness/`。默认 shell、任意文件读写、工作目录切换、DeepSeek 日志上传和包清单上传插件禁用。每个子进程启动都核验实际工具集合，必须恰为 12 个业务工具加官方 `skill`，不符则拒绝模型请求。业务工具由父进程通过临时令牌及回环端口提供，模型不能指定其他合同；提供方 API 密钥不传给子进程。

源码接口、Cordis patch 行为、压缩/恢复和官方 SDK 的具体核验见 [运行时接入核验](DeepSeek-Harness运行时接入核验-20261106.md)。

## 模型、检索与限制

继续使用原有 `/chat/completions` 网关，`llm-pi-ai` 适配器配置 `openai-completions`。在管理界面设置真实上下文容量、最大输出、推理格式与是否启用推理参数；随后运行「验证工具调用与连续回传」。普通文本连接测试不能证明支持工具调用。

默认每轮最多 40 个实际模型 HTTP 请求、30 分钟；重试和压缩请求也计数。连续三次相同工具动作且结果相同暂停。达到限制保存工作，状态为暂停/待继续，不能算完整完成。继续生成新的结果版本；取消会关闭该任务独占的官方子进程并中断上游请求。

Brave 密钥可在界面加密保存，或配置 `BRAVE_SEARCH_API_KEY`。搜索限定政府和司法官网域名；正文读取只允许官方 HTTPS 公网地址，校验 DNS、重定向、类型和大小，保存正文及哈希。摘要仅作线索。未配置、官网失败或效力/适用日期未核实时明确保留限制，不能将未知效力伪装为已验证。

本版官方正文的 `validity` 保守保存为 `unverified`；尚未提供自动认证现行效力的服务。法务仍须按具体案件核实法域和适用日期。没有 Brave 密钥时仍能读取已知官方链接、检索内部固定法律文本，但不声称具备完整联网检索。

Harness 提供执行和上下文管理，模型提供推理。工程贯通不代表法律结论准确，也不保证减少调用或费用。

## 数据、经验与恢复

迁移 `017_harness_review.js` 新增会话、消息、工具事件、幂等调用、冻结来源、法务来源事件及新经验表。每个文件版本使用独立会话。追问在同一会话中另存 `la_reviews` 结果版本，法务处理及最终结论绑定明确 review/version。已确认结果冻结；补充材料更新触发新的固定材料快照。

任务笔记和法务压缩摘要保存目标、事实、定位、已检查和待办。原文、来源、证据及读取覆盖在摘要外保存，随时可重新读取。读取覆盖仅证明材料已读取。

法务保存的改稿、采纳、驳回、结论理由及显式反馈进入 `la_agent_legal_events`。普通追问和 AI 自述不升级为长期经验；整体同意也不自动代表采纳全部 AI 建议。经验提炼核验来源逐字引用、适用条件、重复指纹及个案信息，不经过发布审批。改稿无理由必须保留原因未知的限制。失败来源保留，可从经验页重试。来源撤销后派生经验停用，已引用结果标记需复核，后续会话上下文重建。

Worker 重启用数据库锁识别真正中断的任务；已提交报告先恢复提交结果，已保存问题先恢复等待，不重复调用模型。其他情况调用官方 `resumeSession`。恢复前校验原件哈希、材料范围、模型配置和经验有效性；变化时明确失败或创建新上下文。

会话日志在 `DATA_ROOT/harness`，与 PostgreSQL、`objects` 及历史 `skills` 一起备份。运行中 Agent 持共享锁；备份拿不到独占锁会返回 `BACKUP_AGENT_BUSY`，稍后重试。恢复必须使用独立空数据库和空目录，并保管原 `TOKEN_SECRET` 以解密保存配置。

## 验证与切换

```powershell
npm test
npm run test:integration:isolated
npm run test:agent
node scripts/test-agent.mjs scripts/agent-browser-qa.cjs
node scripts/fixtures/harness/source-smoke.mjs
node scripts/fixtures/harness/product-smoke.mjs
node scripts/fixtures/harness/compaction-restore-smoke.mjs
npm run build
npm run openapi
```

测试 runner 自动启动临时 PostgreSQL，所有业务测试用随机独立测试库。浏览器脚本使用本机 Codex 附带 Playwright 和 Edge。模拟模型只验证流程；真实网关结果与工程验证边界见 [验收记录](Harness工程验证-20261106.md)。旧协议测试原文移至 `backend/test/retired/` 作历史参考；转换、钉钉、Office、鉴权与备份测试继续运行，新断言替代已退役协议，不将删除旧断言解释为旧流程仍可用。

切换顺序：

1. 备份生产 PostgreSQL、合同文件、会话数据和原密钥；在隔离测试环境构建、迁移并验收。
2. 维护窗口停止 API 入队和旧 Worker 拉取。等待已运行旧任务完成；无法完成时停旧 Worker并核对状态，不能在旧进程仍运行时强制覆盖任务。
3. 停止旧服务后执行 `npm run db:migrate`。执行 `npm run harness:cutover` 只读预检。
4. 确认没有旧 running 记录后执行 `npm run harness:cutover -- --apply`，剩余旧任务标记引擎退役，历史数据保留。仍有 running 时脚本拒绝执行，先查明其真实状态。
5. 启动新 API 和 Worker，验证工具兼容、上传、必要问题、追问、证据、改稿、停止恢复、经验和历史导出。新链路失败时保留任务，不自动运行旧引擎。

本次未对现有业务库执行迁移、切换或部署。若需回到旧发行版，只能在停服后按维护预案恢复切换前的完整备份；不要把旧 Worker接入新数据继续执行。
