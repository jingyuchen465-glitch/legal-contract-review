# 完整合同分批审查优化（2026-11-05）

已于 2026-11-05 17:19（北京时间）部署至 https://legal.bi.youmeibi.com 。本次基于线上当前版本应用本轮增量，没有取消、重启或改写既有预审，没有包含工作区其他未提交修改。

## 行为与效果

新预审优先让每批审查点读取完整合同，默认每批 8 项；按整个模型请求的大小预算决定是否分片。保留每项规则覆盖、逐字原文引用校验、固定模型及技能版本、失败批次纠正和断点恢复。已符合的项目要求用一句简短结论、空修改建议和必要证据；风险项目继续要求具体风险及可使用的完整修改条款，无法判断项目保留不确定原因和证据。

对用户此次任务的固定输入做只读回放，使用实际合同、规则、背景和技能文件，模型响应使用替身，无真实模型请求或业务写入：

| 项目 | 原方案 | 新方案 |
|---|---:|---:|
| 提取正文字符数 | 46,020 | 46,020 |
| 原始文本块 | 310 | 310 |
| 审查点 | 51 | 51 |
| 正文分片 | 3 | 1 |
| 审查点批次 | 11 | 7 |
| 预计正常模型请求 | 33 | 7 |
| 最大请求 JSON 字节数 | 60,500 | 117,261 |
| 正文逐字重组校验 | 通过 | 通过 |

调用次数减少约 79%。原方案生成的缓存键与线上 33 个已保存断点全部匹配，新方案不混用这些旧断点。回放统计保存于 `.local/review-performance/production-input-replay.json`，不包含合同正文或密钥。

这验证了请求拆分、完整输入和覆盖，不证明真实模型耗时、漏报率或法律建议质量；真实质量仍需法务标注样本进行对照。输入更长可能改变单次模型耗时，因此不能直接按调用次数比例承诺总耗时。

## 请求预算

- `MODEL_REVIEW_RULE_BATCH_SIZE`：默认 8，有效范围 1–10；非法环境配置回退到默认值。
- `MODEL_REVIEW_INPUT_BUDGET_BYTES`：默认 128,000，有效范围 16,384–512,000，单位是完整请求 JSON 的 UTF-8 字节；非法环境配置回退到默认值。
- 原有 `MODEL_REVIEW_CONCURRENCY=3` 继续控制每个 Worker 进程内的普通逐项审查请求总并发。

字节预算不等同于模型的上下文 token 上限，也不自动发现服务商限制，应结合实际模型的输入、输出能力配置。预算包含系统提示、规则、知识、业务背景、关联材料、技能和正文，以及传输 JSON 中的转义开销；另外预留 8,192 字节供校验反馈使用。发送前再次检查完整请求，含纠错请求。

正文发送时去掉字体和样式等排版属性，保留文本、段落编号、表格行列、页面、OCR 来源及置信度、联合审查文件身份等信息。原始解析结果和原文件保留。关联材料同样保留完整文本，只精简排版属性。

能放入预算时整份正文进入每批请求；超长时按段落完整分片，超大段落按 Unicode 字符边界切分并保留原定位 ID，不截掉尾部或改用摘要。背景或知识本身已无法容纳时，在发送前明确报 `REVIEW_CONTEXT_BUDGET`，不静默丢弃内容。每次模型响应仍验证该批全部审查点及引用。

## 固定执行方案与恢复

创建预审时把执行版本、每批数量、字节预算和提示词版本保存为 `snapshot.reviewExecution`。后续环境配置变更只影响新预审，既有任务按原固定方案恢复。新提示词版本为 `review-1.7-context-budget`。

历史任务没有该字段时使用原来的每批 5 项、16,000 字符分片和 `review-1.6-concrete-clauses` 提示词，其请求内容和缓存键保持兼容。不会把正在执行或已完成的旧任务强制迁移到新拆分方案。

核心实现为 `backend/pilot/review-planning.js`；模型网关读取计划，工作流固定执行设置。前端继续按真实批次显示进度，例如新任务显示“已完成 3/7 批”；剩余时间按实际吞吐粗略估算。
