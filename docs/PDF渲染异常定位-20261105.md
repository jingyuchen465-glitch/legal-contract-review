# PDF 第 1 页渲染失败定位

日期：2026-11-05（北京时间）。状态：已发布线上，原失败任务已生成转换副本，状态为“需核对”。发布详情见 [PDF 渲染修复上线记录](PDF渲染修复上线-20261105.md)。

## 根因

截图对应的 PDF 转 Word 任务在识别第 1 页前失败，错误码为 `PDF_RENDER_FAILED`，已完成页数为 0。使用服务器上的同一原文件和线上转换代码直接调用 `render_page`，稳定复现：

```text
TypeError: '>=' not supported between instances of 'NoneType' and 'int'
```

`pypdfium2.PdfTextPage.get_index` 在采样位置找不到字符时按接口约定返回 `None`。`converter/pdf_word.py` 未检查空值便执行 `char_index >= 0`，导致原本可以提取的文字和页面图像无法返回。转换服务将该异常包装为“PDF 渲染或排版失败，请核对源文件”，不能据此认定文件损坏。

## 修复与验证

- 调用字号接口前检查字符索引是否为 `None`；无索引时沿用现有文字区域高度作为后备字号，继续保留正文及图像。
- 新增回归测试，通过真实 PDF 渲染流程模拟字符位置查询返回 `None`，检查文字、图像和后备字号。修复前出现与线上相同的异常，修复后通过。
- 本地执行 `.local/converter-venv/Scripts/python.exe -m unittest converter/test_pdf_word.py`：6 项中 5 项通过，1 项因本机无 LibreOffice 跳过。
- 服务器在临时目录运行候选代码：原合同 1 页成功渲染，保留 79 个文字区域，处理 1 次字符位置缺失；原文件 SHA-256 与数据库一致且验证前后不变。
- 服务器使用真实 LibreOffice 完成虚构两页 PDF → Word → PDF，确认双栏对齐与表格前留白仍正常。

定位阶段未调用模型、重试业务任务或修改线上转换代码、合同版本与审核结论，仅确认渲染异常已消除及既有排版检查通过。用户随后明确授权“上线”，已发布并通过原失败任务验证；转换稿仍有版式与识别核对项，不能据此宣称完整保真。

## 发布范围

运行时改动仅涉及 `converter/pdf_word.py` 的空值检查；测试改动位于 `converter/test_pdf_word.py`。发布时应以当前线上转换版本为基线，仅合入这处修复，保留回退副本，重启转换服务后检查 `/pdf/health`，再重试截图中的失败任务。不要用历史部署脚本覆盖后续线上版本。
